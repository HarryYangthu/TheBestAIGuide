# 目录与写作规范

## 命名

- 一级目录使用数字前缀稳定排序。
- 技术目录使用小写英文 `kebab-case`，正文默认使用中文。
- 同一知识点只保留一个正式定义，其余位置通过链接引用。
- 每个知识领域以 `README.md` 作为唯一局部导航，不另建重复专题地图。

## 领域内组织

- `01-concepts/` 解释定义、机制、边界和失败模式。
- `02-patterns/` 记录可复用方案、适用条件、代价和反模式。
- `03-cases/` 保存具体系统、代码仓与失败复盘。
- `04-labs/` 保存可运行实验、参数、输出和结论。
- `05-code/` 保存与本领域直接配套的可测试实现。
- 只有存在实际内容时才创建子目录，不用空目录代替知识覆盖。

## 链接

- 仓库内统一使用相对链接。
- 图片统一放在 `assets/`。
- 移动文件时必须同步检查 Markdown 与 Notebook 链接，并从领域 README 验证完整学习路径。

## 内容状态

- `seed`：主题边界或占位。
- `draft`：已有正文，尚未完成审查。
- `reviewed`：结构、事实和来源已审查。
- `verified`：相关代码或实验已实际运行。

## 证据边界

- 总纲中出现一个术语，不等于已经有完整专题。
- 文档中的代码片段，不等于可运行工程。
- Notebook 能打开，不等于实验已验证。
- 架构设计，不等于生产系统已经运行。
