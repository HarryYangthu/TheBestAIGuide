# 目录与写作规范

## 命名

- 一级目录使用数字前缀稳定排序。
- Knowledge 的三个分组目录为 `01 AI Foundation`、`02 Agent Harness`、`03 References`；组内技术目录使用小写英文 `kebab-case`，正文默认使用中文。
- 同一知识点只保留一个正式定义，其余位置通过链接引用。
- 每个组件以 `README.md` 作为唯一局部导航，不另建重复专题地图。

## 组件内组织

- `README.md` 给出范围、总览图、阅读顺序、运行入口与状态。
- 编号 Markdown 与 Notebook 按学习顺序放在组件目录；编号不重复外层组件编号。
- `code/` 保存对应的完整实现，输入样例必须作为真实文件提交。
- `.env.example` 保存 URL、API Key 和模型名的配置项；实际 `.env` 与运行产物不提交。
- 每段可执行代码说明工作目录、输入、预期标准输出及产物位置。
- 原领域结构与已有实现保存在 `10-Knowledge/_archive/`。

## 链接

- 仓库内统一使用相对链接，链接目标中的空格写成 `%20`；命令中的含空格路径用引号括起。
- 图片统一放在 `assets/`。
- 移动文件时必须同步检查 Markdown 与 Notebook 链接，并从组件 README 验证完整学习路径。

## 内容状态

- `seed`：主题边界或占位。
- `draft`：已有正文；可以已经过来源核对或自动审查，但尚未完成人工复核。
- `reviewed`：结构、事实和来源完成明确记录的人工复核。
- `verified`：相关代码或实验已实际运行。

## 证据边界

- 总纲中出现一个术语，不等于已经有完整专题。
- 文档中的代码片段，不等于可运行工程。
- Notebook 能打开，不等于实验已验证。
- 架构设计，不等于生产系统已经运行。

## 学习型文章

具体执行[学习型写作规范](Learning-Writing-Guide.md)：先说清机制，再解释公式与变量，给可检查的算例，最后链接完整源码和实验。新正文保留 `draft`；只有实际执行过的代码或实验才注明限定范围的 `verified`，并标注环境与执行后端。
