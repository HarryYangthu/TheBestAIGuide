# 仓库目录说明

仓库根目录即知识库根目录。`10-Knowledge/` 按 Agent 组件组织；原来的领域目录保存在 `10-Knowledge/_archive/`。

## 顶层目录

| 目录 | 职责 |
|---|---|
| `00-Home/` | 总入口、学习路线、组件地图、规范与状态 |
| `10-Knowledge/` | 12 个核心组件与 3 个增强能力 |
| `10-Knowledge/_archive/` | 原 16 个领域的正文、代码、Notebook 与历史资料 |
| `20-Projects/` | 组合多个组件的完整工程 |
| `90-Sources/` | 论文、文档、标准、数据集与代码仓来源 |
| `99-Inbox/` | 尚未消化、验证或归类的材料 |
| `assets/` | 共享图片、图表和来源记录 |
| `scripts/` | 仓库质量检查与维护脚本 |

## 一个组件内部怎样组织

以已接入的 `10-Knowledge/02_Harness/03-agent-loop/` 为例：

| 文件或目录 | 职责 |
|---|---|
| `README.md` | 阅读路线、配置、运行命令与产物索引 |
| `01-*.md` 至 `04-*.md` | 从基础到进阶逐步实现，每篇先给总览图 |
| `05-*.ipynb` | 沿同一组输入运行并比较实验 |
| `06-*.md` | 把本文实现映射到固定版本的开源源码 |
| `code/` | 完整脚本与验证代码 |
| `notes.txt`、`examples/` | 实际可读取和修改的输入样例 |
| `.env.example`、`requirements.txt` | 模型配置模板和固定依赖 |
| `sources/` | 固定来源、原始文件、节选及许可证 |
| `runs/` | 读者本地运行生成的结果，Git 忽略 |

组件编号只放在外层目录；目录内的 01、02 等表示阅读顺序。各组件按内容需要安排文件，不强制复制相同数量的章节。README 统一列出阅读顺序、输入、命令与产物。

## 归档与依赖

原 `01-concepts/`、`02-patterns/`、`03-cases/`、`04-labs/`、`05-code/` 结构保存在归档中。项目仍可复用这些实现；`scripts/run_python.py` 会发现仓库内的 `src/`。移动文件时需检查相对链接、导入路径、Notebook 和 CI 的工作目录。
