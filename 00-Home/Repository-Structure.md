# 仓库目录说明

TheBestAIGuide 仓库本身就是知识库根目录，不使用额外包裹层。结构优先服务连续学习，而不是按文件格式把内容分散到多个顶层目录。

## 顶层目录

| 目录 | 职责 | 不负责什么 |
| --- | --- | --- |
| `00-Home/` | 全局入口、学习路线、知识地图、范围、规范和状态 | 不存放具体技术正文 |
| `10-Knowledge/` | 按知识领域组织全部学习材料 | 不存放跨领域完整产品 |
| `20-Projects/` | 跨多个领域的完整工程与端到端实践 | 不存放只为解释单个概念的代码 |
| `90-Sources/` | 维护论文、文档、标准、数据集和代码仓来源 | 不直接代替整理后的知识结论 |
| `99-Inbox/` | 暂存尚未消化、验证或归类的材料 | 不作为正式知识入口 |
| `assets/` | 保存共享图片、图表和附件 | 不保存技术正文 |
| `scripts/` | 保存仓库质量检查和维护脚本 | 不保存业务实现 |

## 知识领域内部结构

一个领域只在确有内容时建立对应子目录，不批量制造空占位：

```text
10-Knowledge/<domain>/
├── README.md       # 学习目标、前置知识、阅读顺序和状态
├── 01-concepts/    # 定义、机制、边界与失败模式
├── 02-patterns/    # 可复用方案、适用条件、代价与反模式
├── 03-cases/       # 具体系统、仓库走读与失败复盘
├── 04-labs/        # 可运行 Notebook、输入、输出与实验记录
├── 05-code/        # 与本领域直接配套的可测试代码
└── references.md   # 本领域的一手来源和版本风险
```

阅读顺序不是强制让每个领域都有五类文件，而是确保已有内容可以按“理解 → 决策 → 应用 → 验证 → 实现”连续展开。

## 主题代码与完整项目

- `10-Knowledge/<domain>/05-code/`：服务一个知识领域的示例、库或最小实现。
- `20-Projects/`：同时整合 Context、Tools、Memory、Runtime、Evaluation 等多个领域的端到端工程。

## 内容边界

- Markdown 保存知识结论、设计方法、案例解释和来源链接。
- Notebook 保存实验过程、参数、输出、结论和运行环境。
- 源码工程保存需要复用、测试或持续维护的实现。
- 占位、代码片段、架构方案和构建成功都不自动等于功能或效果已验证。
