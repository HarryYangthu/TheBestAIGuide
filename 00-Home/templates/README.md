# 内容模板：帮助写清楚，不代替内容

模板中的 `〈待填写内容〉` 是写作提示，保留占位是模板本身的用途。复制到正式目录后，填入真实内容，删除提示及不适用的小节；不能只换标题便标成完成。正文要求见 [面向学习的写作要求](../Learning-Writing-Guide.md)，状态定义见 [目录规范](../Conventions.md)。

| 模板 | 放在哪里 | 最关键的交付 |
| --- | --- | --- |
| [概念](concept.md) | 领域 `01-concepts/` | 机制、公式、数值例子与实现的对应 |
| [模式](pattern.md) | 领域 `02-patterns/` | 从可观察的故障，选到能实施的办法 |
| [案例](case.md) | 领域 `03-cases/` | 约束、选择依据和真实结果证据 |
| [实验](lab.md) | 领域 `04-labs/` | 一条运行路径、可解释的输出与对照 |
| [来源卡](source.md) | 领域 `references.md`；跨域记录进入 `90-Sources/` | 固定版本、证据位置和阅读范围 |

知识正文只保留足以解释关键步骤的代码块；完整实现放 `05-code/`，Notebook 放 `04-labs/`。文章链接实验和实现，实验链接概念及源码，代码 README 再链接回文章。链接用实际文件的相对路径，不要求读者从多个片段拼装程序。

领域 README 用一张阅读顺序表连接概念、模式、实验和代码，说明前置知识即可。不要为了填表制造空案例或空实验。数学主题可以侧重推导；系统主题可以侧重状态变化、失败路径和取舍，结构服从内容。
