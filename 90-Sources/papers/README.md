# 论文：核对方法从哪里来，结论能用到哪里

下表只保留贯穿多个学习主题的起点。各领域更详细的论文清单从 [主题来源入口](../README.md) 进入。核验日期：2026-09-06；本索引已读论文摘要和版本记录，用于确认问题、方法范围及固定版本，不将摘要阅读记为全文审查或实验复现。

| 论文与固定版本 | 读它要回答的问题 | 阅读时定位什么 | 证据边界 |
| --- | --- | --- | --- |
| [Attention Is All You Need，v7](https://arxiv.org/abs/1706.03762v7)，2017 首发；该修订为 2023-08-02 | 为什么序列模型可以用注意力组织信息？ | 模型架构与注意力计算；把 Q/K/V 的形状、缩放和加权汇总对应到 [基础模型](../../10-Knowledge/02-foundation-models/README.md) 的实现 | 原文主要报告机器翻译任务；原始 Transformer 不代表之后所有模型的归一化、位置编码与缓存设计 |
| [Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks，v4](https://arxiv.org/abs/2005.11401v4)，2020 首发；修订 2021-04-12 | 为什么要让生成模型读取外部检索结果？ | 检索器与生成器怎样组合，外部知识怎样参与预测；接着读 [RAG](../../10-Knowledge/06-rag-and-knowledge-systems/README.md) 的管线和评测 | 这是特定检索增强模型与任务的证据；企业文档切分、权限和引用是否正确仍需另行评测 |
| [ReAct，v3](https://arxiv.org/abs/2210.03629v3)，2022 首发；修订 2023-03-10 | 为什么行动后要把环境反馈交回模型？ | 推理与行动交替的任务轨迹、外部信息如何修正后续选择；对照 [Agent Core](../../10-Knowledge/03-agent-core/README.md) 的循环 | 论文任务效果不等于任何工具组合都有效；工程上还要处理退出、权限、错误和调用预算 |
| [Lost in the Middle，v3](https://arxiv.org/abs/2307.03172v3)，2023 首发；修订 2023-11-20 | 输入装得下，为什么仍可能用不到其中的信息？ | 多文档问答和键值检索中，相关信息位置怎样影响结果；对照 [上下文工程](../../10-Knowledge/04-context-engineering/README.md) 的失效诊断 | 结论来自论文中的模型、任务和输入设置；不要直接写成“所有新模型在中间位置必然失败” |

读论文时先记录它改变了哪个变量、基线是什么、如何判分，再看提升数字。要引用具体数值，必须读到原文对应表格或图，并保留数据集、模型、采样次数和预算条件；这里只列入口，因此不摘取性能数字。

外部论文的代码不默认随本库安装。可复现入口见 [代码仓](../repositories/README.md)，实际在本库运行的实验从对应领域 `04-labs/` 进入。
