# 来源记录：证据读到哪一步，就写到哪一步

每个领域的具体来源放在该领域 `references.md`，从 [总入口](../README.md) 查找。这里保留跨领域的阅读规则和核验案例。新来源可复制 [来源卡模板](../../00-Home/templates/source.md)。

## 五种不同的阅读结果

| 实际做了什么 | 可以写什么 | 不能据此写什么 |
| --- | --- | --- |
| 页面打开成功 | 链接本次可访问 | 内容正确、结论成立 |
| 阅读摘要、书目或 README | 来源讨论什么、推荐从哪里进入 | 论文每个公式已审查、源码所有行为已确认 |
| 阅读具体方法、表格或函数 | 此版本在给定条件下描述或实现什么 | 其他版本、其他任务也有同样效果 |
| 在小输入上运行对应实现 | 指定环境与样本下的实际输出 | 原论文完整复现、真实生产收益 |
| 固定环境与数据完成复现实验 | 完整配置下的复现结果及误差 | 无条件优于所有方案 |

`reviewed` 和 `verified` 的文件状态按 [仓库规范](../../00-Home/Conventions.md) 使用；上表用于写清具体证据范围，不新增一套内容状态。文章引用的事实应靠近来源链接，不能在文末堆很多链接却不说明各自支持什么。

## 一个实际核验案例：README 与源码不一致

2026-09-06 阅读 HumanEval 固定提交 `6d43fb980f9fee3c892a914eda09951f772ad10d` 时，[README](https://github.com/openai/human-eval/blob/6d43fb980f9fee3c892a914eda09951f772ad10d/README.md) 仍称执行生成代码的调用被注释；但同一提交的 [execution.py](https://github.com/openai/human-eval/blob/6d43fb980f9fee3c892a914eda09951f772ad10d/human_eval/execution.py) 中 `exec(check_program, exec_globals)` 已是可执行语句。

因此本库只确认“该快照存在会执行补全代码的路径”，并注明评测必须使用适当隔离。源码阅读没有替代执行验证；这里没有运行不受信任的补全，也没有对其隔离能力作认证。这说明即使是一手来源，也要确认版本和证据位置，不能只把 README 的话改写一遍。

## 外部内容更新后怎么处理

首先判断变化来自页面搬迁、API 修订还是结论变化。搬迁时更新链接并保留原来源标识；API 修订时记录旧版与新版的差异，并重跑受影响实验；论文换版时核对引用的公式、表格与限制是否改变。访问失败先记录为“本次无法访问”，不要立刻断言论文或数据已经永久失效。

本轮例子：Sutton 教材作者站访问失败，改用出版社书目作为入口，仍注明未读完整电子书；OTel 旧 GenAI 页面声明迁移，已转向新仓库的固定提交。这两种变化需要不同处理，不能统一归为“死链”。
