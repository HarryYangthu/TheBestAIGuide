# State 与 Memory：设计模式

> 状态：seed

本目录后续沉淀可复用方案。当前先明确四类设计问题及其验证重点。

## Checkpoint and Resume

在长任务、外部副作用或人工审批节点持久化可恢复状态。验证重点包括状态完整性、版本兼容、重复执行、幂等和恢复后的环境一致性。

## Memory Write Policy

不要把全部对话直接写成长久记忆。写入前至少判断主体、用途、来源、可信度、敏感度、有效期、重复和撤回要求，并保存来源指针。

## Memory Retrieval

召回不应只依赖向量相似度。先用主体、权限、作用域和时间做硬过滤，再结合相关性、来源质量和任务阶段排序，最后由 Context Builder 决定是否注入。

## Conflict and Forgetting

新旧记忆冲突时不应静默覆盖。系统需要区分追加事件、事实更新、来源冲突、过期和撤回；同时提供删除、失效、合并和审计路径。

## 共同反模式

- 把完整聊天记录当作长期记忆。
- 用 Memory 代替任务状态或数据库事务。
- 不记录来源、时间和主体。
- 跨用户或跨租户召回。
- 只评估召回率，不检查最终任务是否改善。
- 允许过期或错误记忆长期污染后续决策。

## 验证方向

比较无 Memory、全量历史和检索式 Memory，至少观察任务成功、错误记忆使用、冲突处理、Token、延迟、跨主体隔离和删除有效性。
