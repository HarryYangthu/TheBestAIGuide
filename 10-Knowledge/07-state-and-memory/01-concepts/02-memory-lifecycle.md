# Memory生命周期：先判断该记住什么

> 状态：draft | 来源核验：2026-09-06

用户今天说“后续学习材料优先给Python代码”。这条偏好可能对下一次讲解有用，值得作为Memory候选。用户刚才搜索过“上下文”，只是一次操作，是否值得长期保留取决于用途。把全部对话写入向量库，会同时保存临时想法、已失效约束和模型自己猜出的内容，召回得越积极，污染后续回答的机会也越多。

Memory的本质是**为未来使用而选择性保留信息，并在再次使用前检查它是否仍适用**。模型参数记忆、上下文中的短期信息与数据库中的长期记录是不同机制。本域主要研究最后一种，不把写数据库称为给模型训练。

| 类型 | 示例 | 应保存的关键信息 | 常见失效 |
| --- | --- | --- | --- |
| 事件记忆 | 某次预算配置导致输出截断 | 条件、操作、结果、来源 | 把偶然结果当稳定规律 |
| 事实记忆 | 某文档当前版本为v3 | 主体、证据、时间 | 旧版本仍被当最新 |
| 程序性记忆 | 处理长工具结果的步骤 | 适用前提、步骤、验收 | 对不适用任务强套流程 |
| 偏好记忆 | 优先Python示例 | 用户明确表达、适用范围 | 一次性要求被错误永久化 |

这些分类帮助你考虑不同更新规则，不要求建四种数据库。

## 写入与读取是两个决策

写入链路通常是：获得观察→抽取候选→核查来源/主体/用途→去重或处理冲突→持久化。读取链路是：取得当前任务与可信身份→按主体、作用域和时效过滤→相关性检索→判断是否应进入Context。写进去只是获得候选资格，不代表以后每次都注入模型。

本库一条Memory记录含 `subject,key,value,source,updated_at,expires_at,version`。`source`说明证据来自哪里，`version`拒绝基于旧记录版本的写入，`expires_at`控制读取时效。版本只保护并发更新，不判断内容真假或哪条证据更权威；即使携带正确版本，一条错误事实仍可能被成功写入。没有来源的模型猜测应先保留为待验证假设，不能直接升级为“用户说过”。

```python
from state_memory import MemoryStore
store = MemoryStore(":memory:")
m = store.put("learner", "language", "Python", "user-message:1", now=100)
print(store.get("learner", "language", now=101).value)
store.close()
```

上面的数字时间是教学时钟，便于可重复测试。真实系统应统一时区和时间基准，避免客户端可以通过任意填写时间让记录永不过期。接口由可信后端使用，不能直接暴露给模型自行填写主体和来源。

## 什么情况下不要写入

任务的剩余预算、审批等待和工具重试次数属于当前权威State，先按运行状态保存。没有未来用途的完整工具结果可以保存为任务产物，而不加入全局Memory。临时约束应设置任务范围或过期时间。外部文章中的指令只是内容，不是用户偏好，也不能覆写Memory写入规则。

MemGPT研究了有限上下文下的分层记忆管理，说明上下文和外部存储的分工可以被显式设计。但本库实现的是确定性的存储与生命周期规则，没有复现该论文的模型控制策略或实验分数。
