# Tokenization：文本怎样变成模型能计算的序列

> 状态：draft · 来源核验：2026-09-06 · 实验实现字符级 BPE，非某个商用模型的 tokenizer。

语言模型并不直接读取“词义”。它先把文本转换成离散编号，再从嵌入表取出向量。Tokenizer 决定文本怎样切块、每块对应哪个编号，因此影响长度预算、训练难度和某些字符级任务。换一套 tokenizer 而保留原模型权重，通常会让编号和含义错位。

## 1. 从字符串到张量分为四步

常见流程是规范化、预切分、子词切分、编号与特殊 token。规范化可能统一 Unicode 或大小写；预切分可先按空格/标点划边界；子词算法把较长字符串拆成词表内单元；最后添加模型要求的边界或角色标记。是否保留空格、换行和原字符，取决于具体配置，不能假设任何 tokenizer 都能无损还原文本。

设词表大小为 $V$，嵌入维度为 $D$。文本得到编号 $t_1,...,t_T$，嵌入表 $E\in\mathbb R^{V\times D}$，输入表示为 $X_i=E[t_i]$，形状 $(T,D)$。这相当于取表中的若干行；相邻的 token ID 不表示相近语义，语义关系来自训练后的向量。

“一个 token 等于一个汉字/一个词”都不成立。字节、汉字、词片段和标点都可能对应一个或多个 token；数字还可能被切成几段。要精确计算预算，必须用目标模型对应的 tokenizer 和对话模板，而不是按字符数乘固定比例。

## 2. BPE 真正做了什么

BPE 从较小单元开始，反复合并训练语料中出现频率最高的相邻对。教学语料有 `low low lower`，初始把单词拆成字符并附上 `</w>`。`(l,o)` 和 `(o,w)` 都出现三次，预定平局规则后先合并一个，例如 `l+o→lo`，再统计新的相邻对，可能得到 `lo+w→low`。最终规则是一张有先后顺序的合并表。

推理时不再重新统计用户文本中的频率，而是使用训练好的合并优先级。训练时有统计偏好，编码时有固定规则，这是两个阶段。下面的核心代码替换所有不重叠的匹配对：

```python
out, i = [], 0
while i < len(tokens):
    if i + 1 < len(tokens) and (tokens[i], tokens[i+1]) == pair:
        out.append(tokens[i] + tokens[i+1])
        i += 2
    else:
        out.append(tokens[i])
        i += 1
```

真实 byte-level BPE 以字节覆盖任意 UTF-8 文本，再学习常见字节串；一个完整字符可能跨多个 token。配套实现用 Python 字符、空格预切分和显式词尾，只用来观察合并过程。它不模拟 Unicode 规范化、生产词表、特殊 token 安全规则和高效编码。

## 3. WordPiece 与 Unigram 的区别

| 方法 | 训练/选择的基本思想 | 编码时最需要理解的事 |
|---|---|---|
| BPE | 逐步合并高频相邻单元 | 使用已学习的合并优先级 |
| WordPiece | 学习有利于语言建模的子词词表 | 常见实现按最长可匹配片段贪心切分，词中片段可带标记 |
| Unigram | 给候选子词赋概率，再优化并缩减词表 | 可用动态规划寻找高概率分割，也可采样多个分割 |

WordPiece 的具体训练实现并非所有库都相同，不应把教学近似打分式当成唯一官方算法。Unigram 假设分割 $s=(u_1,...,u_m)$ 的概率为 $P(s)=\prod_jp(u_j)$，最优分割最大化 $\sum_j\log p(u_j)$。同一字符串有多个分割；训练时对子词切分做采样可以形成数据扰动。它的“概率最高切分”不同于简单选择最长 token。

例如 `ab` 可切为 `[ab]` 或 `[a,b]`。若 $p(ab)=0.1,p(a)=0.4,p(b)=0.4$，则两个概率为 0.1 与 0.16，Unigram 会偏向后者。该例只说明分割打分，完整训练还涉及整套词表的概率估计与删除策略。

## 4. 特殊 token 和聊天模板为什么会影响结果

BOS/EOS 表示序列开始/结束，PAD 用于批量补齐；角色、工具结果和消息结束标记帮助模型区分交互结构。这些标记由训练协议定义，手写看似相同的字符串未必得到同一 token。模型是否自动添加 BOS、模板末尾是否生成 assistant 前缀，都要用实际模板检查。

Padding 需要正确的 attention mask 与 loss mask。把 PAD 当普通目标参与损失，模型会学大量无意义填充；把聊天角色边界丢掉，模型可能把工具输出误当用户指令。字符串中长得像特殊标记的用户内容，应该按 tokenizer/模板的受支持方式转义或编码，不能任意允许它变成控制 token。

## 5. 设计系统时要做的检查

保存 tokenizer 版本、词表、合并规则和聊天模板，与模型一起版本化。用中文、代码、emoji、数字、空白符构造输入回归；检查编码后的长度以及解码是否符合预期。截断尽量在结构边界执行，避免切掉指令、JSON 尾部或跨 token 的多字节字符。模型 token 预算与人类语义完整性需要分别检查。
