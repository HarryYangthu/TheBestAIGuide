# 推理模型：增加计算为什么有时有用，有时只会把错误写长

> 状态：draft · 来源核验：2026-09-06 · 本文解释机制与验证设计，不评价当前商业模型排名。

“推理能力”需要用能检查的任务定义。对于算术，检查数值与单位；对于代码，检查执行结果与测试；对于方案设计，检查约束、证据和实际实验。更长的推理文本只是一个过程现象，不是正确性的证明。

## 1. Chain-of-Thought 改变了哪一步

Chain-of-Thought（CoT）让模型在输出最终答案前生成中间步骤，使后续 token 能利用这些步骤继续计算。它没有自动修改模型参数，也没有保证步骤忠实反映模型内部全部计算。某些模型通过额外训练学会更有效地分配推理过程；是否能访问完整内部过程是另一个问题，系统应围绕可验证的答案、工具记录和简明依据验收。

例如“两箱各12件，取走7件，剩多少”，中间步骤明确为 $2\times12=24$、$24-7=17$，便于发现把“各12件”误解成总共12件的错误。对这类精确计算，直接调用可信计算工具往往比要求模型反复口算更稳。自然语言推导适合组织思路，工具负责可确定执行的部分。

## 2. Test-time Compute 可以花在不同位置

| 方式 | 额外计算花在哪里 | 对应风险 |
|---|---|---|
| 单条更长推理 | 展开同一解法 | 早期错误被继续合理化 |
| 多条候选/self-consistency | 不同采样路径，归一化答案后投票 | 路径相关，重复同一错误 |
| 搜索/分支修正 | 展开有潜力的中间状态 | 分支爆炸、局部评分偏差 |
| Verifier 重排 | 验证候选结果再选 | 判断器误判或被候选文本误导 |
| 工具检查 | 执行代码、约束求解、检索证据 | 工具/环境/输入本身可能错误 |

Self-consistency 的投票对象应是规范化后的答案，例如 `0.5` 与 `1/2` 归为同一值；重复措辞不能算独立证据。对开放式文章没有天然唯一答案，投票通常比精确任务更难定义。

若每条候选独立成功概率为 $p$，至少一条成功概率是 $1-(1-p)^k$。例如 $p=0.4,k=3$ 得0.784。这只是“候选池包含正确答案”的概率，实际选择器能否挑出来另算；候选存在相关性时这个公式也不成立。不能用 oracle 的 pass@k 冒充系统单次交付成功率。

## 3. Verifier 与 Process Reward 分别验证什么

结果验证器检查最终答案，例如代码测试通过、数学答案一致、输出满足约束；过程验证器检查步骤局部是否有效。Process Reward Model 用步骤标注训练评分，可帮助搜索，但局部正确步骤串起来仍可能没有解决原问题。测试覆盖不足时，通过测试的代码也可能错。

设计一个可靠验证器先写输入输出契约，再准备正例与反例。代码任务要包含隐蔽边界、错误类型和资源限制；引用任务要检查证据内容是否支持主张，不能只检查 URL 存在。让生成模型给自己的长答案打高分很便宜，但没有独立依据时容易循环自证。

```python
from fractions import Fraction
# 教学：三条候选来自人工构造，不是模型调用结果
candidates = ['17', '19', '34/2']
verified = [x for x in candidates if Fraction(x) == 2*12-7]
assert verified == ['17', '34/2']
```

这段代码故意用可判定的算术表达式说明验证与文风无关。复杂科研结论没有如此完美的 verifier，必须说明哪些约束可硬检查，哪些仍依赖实验或专家判断。

## 4. 预算怎样分配才可比较

定义最终效用 $U=Q-\lambda C$，其中 $Q$ 为任务质量，$C$ 为推理/工具总成本，$\lambda$ 表示代价权重；或者更清楚地把成本和时限当硬约束，只在约束内比较成功率。不要让某方法用十倍预算，再把收益全部归因于架构。

可以先尝试一个低成本解法；如果可验证条件失败，再增加候选或调用工具。只有在失败信号有区分能力时，这种自适应策略才有价值。若触发条件只是模型自报“我不确定”，需要验证它是否真的对应高错误率。

## 5. 推理边界与常见失败

| 失败 | 观察方式 | 更有效的改动 |
|---|---|---|
| 问题理解错了 | 列出目标、已知条件和单位 | 澄清输入或结构化约束 |
| 事实基础错误 | 检查原始来源与时间范围 | 检索/工具，不能靠多想补事实 |
| 算法正确但执行错 | 实际运行、单元与边界测试 | 可信执行环境与测试 |
| 长链漂移 | 对照每个中间产物与目标 | 状态外置、分阶段验证 |
| 候选一致但都错 | 检查方法与证据是否独立 | 引入不同方法/不同验证信号 |

推理模型也不能保证解决训练外的任意新算法问题，更长输出还会增加时延和资源。评测需固定题集、预算、采样配置与选择器，并报告最终交付正确率、成本分布和失败分类。
