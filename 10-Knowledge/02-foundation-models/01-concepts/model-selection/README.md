# 模型选择：用自己的任务建立可复查的决策

> 状态：draft · 来源核验：2026-09-06 · 下表与代码数据均为虚构教学数据，不是模型排行榜或实测。

选型的目标是：在任务、成本、延迟和数据约束下，找到可稳定完成工作的模型配置。这里的“配置”包括模型版本、提示、模板、推理预算、工具和解码方式。只看模型名字，无法复现选择过程。

## 1. 先设硬约束，再比较质量

| 维度 | 应收集的证据 | 常见误判 |
|---|---|---|
| 任务能力 | 自有任务集，最终结果与失败切片 | 用通用榜单替代业务成功率 |
| 延迟与吞吐 | TTFT、完成时延p50/p95、目标并发 | 只测一个短请求 |
| 成本 | 完成任务总费用，含重试与工具 | 只比每百万输入token价格 |
| 上下文 | 真实长任务的约束遵守与引用 | 最大窗口等于有效利用长度 |
| 数据与部署 | 可用区域、留存策略、许可、接入条件 | 开放权重自动等于满足所有隐私要求 |
| 工具/格式能力 | Schema 合法率、参数正确、错误恢复 | 能生成JSON就等于能调用工具 |

开放权重便于检查和部署，但还需考虑许可、运维、硬件与更新成本；托管模型减少部署负担，可能受配额、网络和版本变更影响。这里不固定推荐某家产品，实时价格、能力和条款应在实际选型时重新核验。

## 2. 任务集怎样才能代表真实使用

从实际请求按任务类型、长度、难度、来源抽样，明确预期结果和允许工具。开发集用于调提示与预算，保留测试集用于最终比较。对训练污染敏感的任务，可以增加新构造的问题、参数变化和可执行验证，但“新写一道题”不自动等于完全无污染。

同一任务给所有候选，形成配对比较。记录每个任务是否成功、花费和错误原因；非确定采样需重复运行，且不要把同一题的重试当作完全独立新题。样本很少时，小幅均值差不足以排序，先查看差值分布和关键失败。

## 3. 为什么便宜模型可能更贵

设每次尝试平均费用为 $c$，独立成功概率为 $p$，如果无限重试直到成功且每次情况相同，则成功前预期尝试数为 $1/p$，成本为 $c/p$。这是一个简化模型；真实错误可能高度相关、存在重试上限和人工兜底，不能机械使用。

更稳妥的实测指标是：$\mathrm{cost\_per\_success}=\frac{\text{全部任务总费用}}{\text{成功交付任务数}}$，失败任务已产生的成本也包含在分子。与此同时必须报告成功率，否则拒绝所有难题、只交付少数简单题也可能显得便宜。

教学例中 A 成本低但格式错误频繁，B 成本高但重试少。是否选择 B 取决于完整任务成本和时限，不能仅按单次调用费用做决定。

## 4. 用 Pareto 筛选，而不是随便加权

如果模型 A 在质量不低、成本和延迟不高的同时，至少一项更好，则 A 支配 B，B 可以先从候选中排除。剩余 Pareto 集再按业务取舍。硬要求例如“只能本地运行”“p95不超过5秒”应先过滤，不能给它一个权重后让其他优点抵消。

```python
# 纯教学数据；cost单位是任意单位，不代表真实价格
models = [
    dict(name='A', success=.80, cost=.2, p95=3.),
    dict(name='B', success=.90, cost=.4, p95=4.),
    dict(name='C', success=.78, cost=.3, p95=4.),
]
def dominates(a, b):
    no_worse = a['success'] >= b['success'] and a['cost'] <= b['cost'] and a['p95'] <= b['p95']
    better = a['success'] > b['success'] or a['cost'] < b['cost'] or a['p95'] < b['p95']
    return no_worse and better
frontier = [m['name'] for m in models
            if not any(dominates(other, m) for other in models)]
assert frontier == ['A', 'B']
```

A 支配 C，但 A 与 B 各有优劣。若要求成功率至少0.88，B才可入选；若成本硬上限0.3且质量要求不变，这组候选都不满足，正确结论是“暂无可用方案”，不是偷偷放宽指标。

## 5. 路由和回退同样需要评测

把简单任务交给便宜模型、困难任务升级，只有路由器能识别困难且升级有收益时才节约。先测路由器错分：难题误分到弱模型会直接损害结果。回退模型的接口、上下文、工具输出格式也需兼容，不能把上游的部分状态直接塞给另一模型就认为无缝接续。

最后保存可复查的选型表：模型精确版本、评测日期、任务集hash、提示/工具版本、预算、质量及区间、p95、单位成功成本、未覆盖场景和最终决策理由。后续模型升级或任务分布变化时复跑同一基线，避免每次重新凭印象选择。
