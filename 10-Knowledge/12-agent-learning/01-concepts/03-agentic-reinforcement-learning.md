# Agentic RL：从环境反馈学习动作，而不是给思考打高分

> 状态：draft · 来源核验：2026-09-06 · 教学示例均为本库原创，非生产成绩。

Agent 做了十次工具调用，最后修复失败。仅凭最后的 0 分，我们不知道问题出在定位、编辑还是验证。Agentic RL 的核心困难就是：模型产生动作，环境改变并返回观察，训练如何把最终结果分配给沿途的决策。

## 先定义环境，再谈算法

环境包含重置函数、动作接口、转移和验收。仓库任务应从固定 commit 和干净工作区开始；文件、数据库和浏览器状态是环境状态。模型通常只能看到部分状态，因此它实际上根据观察历史 $h_t$ 决策，而不是直接读取完整真实状态。

$$J(\theta)=\mathbb E_{\tau\sim\pi_\theta}\left[\sum_{t=0}^{T-1}\gamma^t r_t\right].$$

$\pi_\theta(a_t|h_t)$ 是模型策略，$r_t$ 是第 $t$ 步奖励，$T$ 是轨迹长度，$\gamma\in[0,1]$ 决定未来奖励折扣。用 $\gamma<1$ 会偏向更早获得奖励；如果任务不应该因必要的长过程被惩罚，就要明确这种取舍，不能无意识套默认参数。

## PPO 与 GRPO 分别解决什么

策略梯度提高“比预期更好”的动作概率，降低“比预期更差”的动作概率。这个相对好坏叫优势 $A_t$。PPO 用新旧策略概率比 $\rho_t=\pi_\theta(a_t|h_t)/\pi_{\rm old}(a_t|h_t)$ 限制更新幅度：

$$L_{\rm clip}=\mathbb E\left[\min\left(\rho_t A_t,\operatorname{clip}(\rho_t,1-\epsilon,1+\epsilon)A_t\right)\right].$$

训练最大化这个目标。$\epsilon$ 是裁剪宽度。假设 $A_t=1,\epsilon=.2,\rho_t=1.5$，贡献被截为 1.2，避免一次更新过度提高动作概率。负优势情形也要检查两个分支，不能直接把所有概率比硬截断后当成同一算法。实际 PPO 通常还训练 value 网络并加入其他损失。

GRPO 从同一道题采样一组候选，以组内奖励比较构造优势，可避免使用单独的 value 模型。最简结果奖励形式是：

$$A_i=\frac{R_i-\overline R}{s_R+\varepsilon}.$$

$R_i$ 是第 $i$ 条候选的奖励，$\overline R$ 是本组均值，$s_R$ 是标准差，$\varepsilon$ 用于避免除零。对于 `[0,1,1,0]`，使用总体标准差得到 `[-1,1,1,-1]`；如果所有奖励一样，优势为零，这组数据没有提供区分信号。不同实现的标准差、长度归一化、KL 估计和采样过滤可能不同，阅读实现时要逐项核对。

## 为什么整条轨迹同分会浪费样本

最终测试通过时，把正优势赋给全部生成 token 会连无效绕路一起鼓励。解决办法包括更短的可验收子任务、经过校准的过程奖励，以及保留最终验收的分层目标。过程奖励也会被投机：按“调用测试次数”奖励，Agent 可能反复测试而不修复。

| 故障 | 可做的改动 | 必须付出的代价 |
|---|---|---|
| 一组候选全部失败 | 调整任务难度、增加有效示范 | 需要控制课程偏差 |
| 只学会刷过程分 | 用外部结果验收、红队反例 | 需要更贵的验证 |
| 训练和上线环境不一致 | 固定工具、容器和接口版本 | 增加环境维护成本 |
| 长轨迹更新不稳定 | 限制长度、分段或改优势估计 | 可能丢失长程依赖 |
