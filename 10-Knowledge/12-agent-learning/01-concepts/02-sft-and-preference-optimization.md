# SFT 与偏好优化：到底在提高哪一种输出的概率

> 状态：draft · 来源核验：2026-09-06 · 教学示例均为本库原创，非生产成绩。

同样看见“文件不存在”，一个 Agent 会继续重复打开旧路径，另一个会先列目录。SFT 可以教它模仿第二条动作序列；偏好优化可以让第二条序列相对第一条更容易被生成。二者都在改模型参数，不能与修改 Prompt 或检索记忆混为一谈。

## SFT 的目标和 Loss Mask

给定串行化轨迹 $x_1,\ldots,x_n$，监督微调最小化：

$$L_{\mathrm{SFT}}=-\frac{\sum_{i=1}^n m_i\log p_\theta(x_i\mid x_{<i})}{\sum_{i=1}^n m_i}.$$

$m_i\in\{0,1\}$ 是位置 $i$ 的掩码。只训练模型应该生成的 Assistant 文本、工具名和参数；用户输入、系统说明、工具返回通常作为条件而不作为预测目标。注意：屏蔽某个 token 的损失，并不会让模型看不到它。没有至少一个目标 token 的样本必须丢弃或报错。

假设六个 token 的正确预测概率为 `[.8,.8,.5,.25,.9,.9]`，只有第三和第四个是动作参数，损失为 $-(\log .5+\log .25)/2\approx1.0397$。代码与公式一致：

```python
import math
p = [.8, .8, .5, .25, .9, .9]
mask = [0, 0, 1, 1, 0, 0]
loss = -sum(math.log(q) for q, m in zip(p, mask) if m) / sum(mask)
```

真实训练使用 tokenizer 的聊天模板和 token 边界建立标签，通常把非目标位置置为框架规定的 ignore index。不要按字符串长度切标签；汉字、特殊 token 和工具消息边界都会使字符偏移与 token 偏移不同。

## DPO 为什么需要同一个问题的两个答案

DPO 使用同一输入 $x$ 的优选回答 $y^+$ 和较差回答 $y^-$。固定参考模型 $\pi_{\rm ref}$，定义：

$$z=\beta\left[\log\frac{\pi_\theta(y^+|x)}{\pi_{\rm ref}(y^+|x)}-\log\frac{\pi_\theta(y^-|x)}{\pi_{\rm ref}(y^-|x)}\right],\qquad L=-\log\sigma(z).$$

序列对数概率是目标 token 对数概率之和。$\beta>0$ 控制相对参考策略的约束尺度，$\sigma$ 是 sigmoid。优化推动优选相对较差回答的对数概率比提高；它并不把人工分数直接当作输出概率。若 $z=0$，损失是 $\log2$；若 $z=2$，损失约为 $0.127$。损失下降只说明符合训练偏好，是否更会完成任务仍要独立评测。

对 Agent 轨迹，必须保证两条候选来自相同任务和兼容环境。一个候选有数据库访问权、另一个没有，比较结果就混入了权限差。给长轨迹排序还容易偏好冗长解释；是否做长度归一化会改变目标，不能偷偷更换公式后仍称为原始 DPO。

## 该选哪一个

| 症状 | 优先方案 | 开始前检查 |
|---|---|---|
| 经常生成非法工具参数 | 工具 SFT 或约束解码 | Schema 是否一致、标签是否正确 |
| 两条合法方案有明确优劣 | 偏好优化 | 优劣能否用独立标准解释 |
| 工具超时、权限不足 | 修 Runtime 或工具 | 训练不会修复不可用的 API |
| 新知识没有进入上下文 | 检索或数据接入 | 不应先用微调记住不断变动的信息 |

[实验](../04-labs/01-trajectories-and-rewards.ipynb)只计算损失、掩码和奖励，不训练语言模型。真实训练还需要模型、优化器、批处理、精度和数据版本配置，并回归合法调用率、任务成功率与越权率。公式来源为[DPO 原论文](https://arxiv.org/abs/2305.18290v3)，更多条目见[来源索引](../references.md)。
