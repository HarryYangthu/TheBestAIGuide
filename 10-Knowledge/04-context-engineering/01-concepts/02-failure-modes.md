# 上下文失败模式

> 状态：draft
> 目的：用可观察症状定位信息选择和组织问题，而不是把所有失败都归因于模型。

## 失败模式总表

| 模式 | 定义 | 常见症状 | 优先检查 |
| --- | --- | --- | --- |
| Poisoning，中毒 | 错误信息被写入状态或记忆，并在后续反复使用 | 多轮稳定地产生同一种错误 | 错误首次出现在哪一轮，谁将其提升为事实 |
| Distraction，干扰 | 大量历史或次要信息抢占注意力 | 重复旧动作、忽略当前目标、输出冗长 | 历史是否未分层，当前步骤是否不突出 |
| Confusion，混淆 | 无关或重叠的信息让模型选错规则、工具或证据 | 调错工具、参数混用、引用无关片段 | 工具和候选证据是否过多且描述相近 |
| Clash，冲突 | 上下文中同时存在互不兼容的事实或指令 | 行为摇摆、随机选择版本、无法稳定复现 | 来源、时间、权限和适用范围是否明确 |
| Rot，腐化 | 随长度增加，关键信息可用性下降 | “明明在上下文里”却没有使用 | 关键信息位置、重复度、窗口利用率 |
| Overflow，溢出 | 输入超过模型、网关或应用限制 | 截断、请求失败、关键尾部丢失 | 哪一层截断，是否为输出预留空间 |
| Leakage，泄露 | 不该进入模型或日志的信息被带入 | 密钥、PII、跨租户数据出现在 Trace 或输出 | 访问控制、脱敏和遥测内容策略 |
| Injection，注入 | 不可信内容伪装为系统指令 | 模型违背任务或调用危险工具 | 是否保留数据/指令边界，动作是否有独立授权 |

## 1. Context Poisoning

典型链路：

```text
一次错误推断
  -> 被摘要为“已确认事实”
  -> 写入状态或长期记忆
  -> 后续每轮都读取
  -> 错误变得稳定且难以发现
```

修复重点不是“再提示模型仔细一点”，而是找到错误被持久化的位置：

- 事实写入前需要来源或验证状态；
- 失败结果和推测不能默认进入长期记忆；
- 新证据推翻旧事实时要留下替换关系；
- 能从系统记录读取的事实，不让模型自行回忆。

## 2. Context Distraction

长任务容易把完整历史当作唯一状态。结果是模型持续关注已经完成的步骤，而当前目标和未决问题被淹没。

处理顺序：

1. 把“当前目标、当前步骤、未完成项”做成结构化工作状态。
2. 将已完成历史降级为摘要或可回读引用。
3. 删除重复工具输出和无后续价值的中间文本。
4. 用任务结果评估压缩是否损害能力。

## 3. Context Confusion

常见来源：

- 一次向模型暴露几十个相似工具；
- RAG 返回多个主题接近但不适用的片段；
- 同一字段在不同工具中使用不同含义；
- 示例与真实任务的格式相似，但约束不同。

可用的修复包括工具路由、命名空间、Schema 去歧义、metadata 过滤和 rerank。仅扩大窗口通常不会解决混淆。

## 4. Context Clash

冲突并不总是错误。例如“默认 30 天退款”和“企业合同 60 天退款”可能分别适用于不同范围。问题在于上下文丢失了条件。

冲突项至少要携带：

- 来源与权威主体；
- 生效和失效时间；
- 适用对象、环境或版本；
- 是否已被替换；
- 无法消解时的升级策略。

## 5. Rot 与 Overflow

`Overflow` 是容量问题，通常可直接观测；`Rot` 是有效性问题，即使没有达到硬上限也可能发生。诊断时不要只统计总 Token，还要看：

- 目标和关键约束所在位置；
- 重复片段占比；
- 检索证据覆盖率；
- 无关工具定义数量；
- 关键信息在不同长度、不同顺序下的召回和使用情况。

## 6. Injection 与 Leakage

Prompt Injection 首先是信任与授权问题，不只是文本过滤问题。

防线应分层：

1. 标记外部内容为不可信数据。
2. 只向模型暴露当前任务需要的工具。
3. 工具 Runtime 独立执行参数、身份和权限校验。
4. 高风险动作要求明确批准或二次确认。
5. 日志和 Trace 默认不记录敏感正文，按需开启且脱敏。
6. 用对抗任务测试间接注入、数据外泄和权限提升。

## 排障流程

```text
确认失败的最终状态
  -> 找到首次偏离预期的步骤
  -> 对比该步实际 Context 与期望 Context
  -> 判断是缺失、错误、过期、冲突、无关还是越权信息
  -> 定位来源、选择、转换、排序或执行层责任
  -> 构造最小复现与反例
  -> 修复后加入回归任务
```

## 不要这样修

- 每次失败都向系统提示追加一条规则。
- 只靠更大的窗口容纳所有历史。
- 用摘要覆盖原文，却不保留来源和回读入口。
- 通过删除错误日志让上下文“更干净”。
- 把工具权限交给 Prompt 约束。
- 只观察最终回答，不检查环境状态和工具结果。
