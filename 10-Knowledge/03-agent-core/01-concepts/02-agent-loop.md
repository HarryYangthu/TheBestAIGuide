# Agent Loop：每一轮究竟改变了什么

> 状态：draft | 来源核验：2026-09-06 | [实现](../05-code/agent-loop-python/src/agent_loop/loop.py)已通过离线测试

继续用“搜索上下文预算资料”这个任务。第一轮没有检索结果，策略提出搜索；运行时执行搜索，把结果写入 State。第二轮策略能看到刚才的结果，于是生成带文档编号的答案。这两轮的差别是**第二次决策得到了第一次行动产生的新信息**。

| 轮次 | 决策前已知内容 | 动作 | 程序写入的事实 |
| --- | --- | --- | --- |
| 1 | 只有查询“上下文” | `search(query="上下文")` | 调用ID、成功标志、两条文档 |
| 2 | 查询与上述观察 | `finish(answer=...)` | 答案、终止原因、总决策数2 |

完整代码里依次执行四件事：复制状态给模型；检查动作结构；按注册表执行工具；保存工具结果。复制是为了使适配器无法通过修改 Python 对象偷偷修改运行状态。它不是安全沙箱：恶意 Python 代码仍然有当前进程权限，实际不可信代码必须放入隔离环境。

```python
from agent_loop import EvidenceModel, default_tools, run_agent
state = run_agent(EvidenceModel(), default_tools(), "上下文", max_steps=8)
print(state.steps, state.stop_reason)
print(state.answer)
```

`EvidenceModel` 是明确写出的规则策略。它让你先看清数据流；替换模型不应改变预算、权限和状态更新规则。

## 终止必须是代码里的条件

| 情况 | 本实现的处理 | 原因与局限 |
| --- | --- | --- |
| 合法 `finish` | `completed/model_finished` | 仅表示控制流程完成，尚未验证答案 |
| 达到最大决策数 | `stopped/max_steps` | 包含结束动作在内均计一步，保证上界 |
| 相同动作、参数和结果重复两次 | `stopped/no_progress` | 防止同一查询无效循环；不适用于本来就需反复采样的任务 |
| 模型动作格式错误或适配器异常 | `failed/invalid_model_output` | 最小实现直接停止，不假定能安全修复 |
| 工具返回Python专有对象、混合类型字典键或非有限数 | `invalid_output`失败观察 | 在签名和Trace之前拒绝，避免后续序列化崩溃 |
| 工具参数错误、未知工具、无权限 | 写成失败观察交回策略 | 策略可以改动作；运行时不替它放宽权限 |

无进展检测比较的是动作与结果，不仅是工具名。连续两次 `search` 可能使用不同查询词并带来新信息，不能一概阻止。相反，只换调用ID却仍执行完全相同查询，不应被当作进展。本例采用结果签名计数，它是可解释的保护规则；真实研究任务应基于新证据数、已完成子目标等任务信号判断进展。

这里的“两次”是本次运行内累计两次，不要求相邻。若动作依次是查询 A、查询 B、再次查询 A，且两次 A 的结果相同，第三步就会停止。新结果若只多了时间戳也可能避开重复检查，所以它不能代替业务上的进展判定。默认 `repeat_limit=2` 是运行参数，不是 Agent 的通用定律。

## 预算怎样估算

若每轮模型输入/输出token分别为 $I_t,O_t$，单价为 $p_i,p_o$，工具费用为 $q_t$，总费用为

$$C=\sum_{t=1}^{T}(p_i I_t+p_o O_t+q_t).$$

式中的单价需要先统一为“每token费用”。它说明只限制轮数不够：八轮每轮输入十万token仍可能很贵。本实现仅限制步数，未模拟实际token和计费；生产版本应在模型适配器返回 usage 后扣账，并在发起请求前检查剩余预算。预算字段来源必须是服务端计量，不接受模型自己声明“本次免费”。

例如，两轮输入分别为 1000、1800 token，输出分别为 100、200 token；假设教学单价为每百万输入 1 元、输出 4 元，工具两次共 0.02 元，则总费用为 $2800/10^6+300\times4/10^6+0.02=0.024$ 元。这里没有使用任何供应商报价。第二轮包含第一轮历史时，会按实际请求再次计入输入；缓存费用需按供应商口径单列。调用后 `usage` 只能核对已发生费用，硬预算还需在请求前约束最大输入、最大输出和工具开销。

## 追踪什么，不追踪什么

JSONL Trace 每行记录一个 `run_id/seq/kind/data` 事件。把 `tool_call` 与 `tool_result` 用调用ID连接，能定位“选错工具”“参数错了”；判断“工具正确但答案错了”还需结合返回的 `state.answer`，本例 Trace 的 `run_finished` 只保存状态、原因和步数，不含最终答案。记录动作依据的简短摘要可以帮助诊断，但无需持久化模型的隐藏思维过程。本实现收集事件后落盘，因此不是崩溃后恢复日志；持久恢复见 [State](../../07-state-and-memory/01-concepts/01-state-and-checkpoints.md)。
