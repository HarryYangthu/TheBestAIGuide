# 可信 AI：把“看起来可靠”拆成可检验的问题

> 状态：draft · 来源核验：2026-09-06 · 校准实验为人工生成的二分类数据。

准确率、置信度和安全性是三个不同对象。一个模型可以多数时候答对，却在答错时非常自信；也可以预测准确，但泄露训练数据或对某类用户明显更差。可信性需要分开检验，不能合成一个没有口径的“可信分数”。

## 1. 不确定性来自哪里

偶然不确定性来自观测本身的信息不足，例如传感器噪声；认知不确定性来自模型没学到或没见过这种情况。更多相同质量的数据不一定消除前者，但新数据、模型改进可能降低后者。单次 softmax 最大值无法可靠区分两者，语言模型自述“我有90%把握”也不是经过统计校准的概率。

真正的校准要求：在模型给出约 80% 置信度的样本中，大约 80% 应正确。它是样本集合上的频率性质，不能保证某一个 80% 样本正确。多分类还要说明是校准每一类概率，还是只校准最大概率对应的预测。

## 2. 怎样测量并修正校准

把置信度分为 $M$ 个区间 $B_m$，常见 ECE 为：

$$\mathrm{ECE}=\sum_{m=1}^{M}\frac{|B_m|}{n}\left|\mathrm{acc}(B_m)-\mathrm{conf}(B_m)\right|.$$

例如 100 个样本中，50 个平均置信度 0.9、实际正确率 0.7，另 50 个的平均置信度和实际正确率都为 0.6，则 ECE 为 $0.5\times0.2+0.5\times0=0.1$。ECE 会受分箱和样本量影响；两个模型不能用不同分箱随意比较。还应该报告负对数似然 NLL、可靠性表/图和 Brier 分数。二分类 Brier 为 $\frac1n\sum_i(p_i-y_i)^2$，越低越好。

温度缩放调整 logits 而非训练全部模型：$p_T=\operatorname{softmax}(z/T)$，在独立校准集选择 $T>0$ 使 NLL 最小，再固定它评测测试集。$T>1$ 让分布更平，$T<1$ 更尖；因为各 logit 除以同一正数，argmax 不变，分类准确率可保持不变而置信度改善。它不能修复错类，也不保证分布变化后仍然校准。

```python
candidates = np.linspace(0.5, 6.0, 111)
temperature = min(candidates,
    key=lambda t: binary_nll(calibration_logits, calibration_labels, t))
report = calibration_metrics(test_logits, test_labels, temperature)
```

## 3. 鲁棒性与分布外识别

测试集要含合理扰动，例如错别字、无关段落、表格列顺序变化和不同噪声强度，并检查标签是否仍应保持不变。改变一个否定词可能真的改变标签，不能当作“不应影响结果”的扰动。对抗鲁棒性关注刻意选择的扰动，普通噪声测试通过并不证明能抵抗攻击。

分布外 OOD 输入可能来自新设备、新语言或新任务。最大 softmax 很高也可能是 OOD；应结合输入特征、拒答策略与人工抽检。拒答可以降低已接受样本的风险，但也减少覆盖率。因此报告风险—覆盖率关系，而不是只展示拒绝大量难题后的准确率。

## 4. 公平、解释、隐私怎样落到指标

| 维度 | 应检查的具体问题 | 不能直接推出的结论 |
|---|---|---|
| 公平与偏差 | 不同群体的样本量、漏报/误报、标签质量 | 总体准确率高不代表各群体相同 |
| 可解释性 | 特征变化是否影响输出；解释能否预测反事实行为 | 好听的理由不等于真实决策原因 |
| 隐私 | 是否记忆并暴露样本、访问与删除是否受控 | 去掉姓名不等于无法重新识别 |
| 模型安全 | 提示注入、越权工具调用、数据外传路径 | 模型拒答能力不替代权限控制 |

公平指标需要业务含义。例如 equalized odds 关注不同群体的真阳性率和假阳性率；demographic parity 关注阳性预测比例。基率不同的情况下，这些目标可能冲突，不能宣称一个指标“消除了偏见”。小群体样本不足时必须给不确定性，而不是用几个样本排名。

解释性方法也需要反事实检查。把 attention 权重直接当作因果解释会忽略 Value、残差和后续层；对输入遮挡观察变化只能提供特定干预下的证据。差分隐私通过限制单个样本对发布结果的影响给出数学保护，但需要明确邻接定义、$\epsilon,\delta$、组合与实现假设；这里只介绍概念，不把普通加噪声称为差分隐私。

## 5. 系统层的可靠性如何验收

把合法任务和攻击/越权任务一起纳入回归，分别观察任务成功与违规动作。只提高拒绝率可能让系统什么都不做；只看完成率又可能鼓励突破边界。用户身份、授权范围和敏感数据访问应由代码验证，模型的解释不能代替实际鉴权。
