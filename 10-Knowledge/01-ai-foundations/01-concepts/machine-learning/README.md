# 机器学习：用什么数据，学什么目标，如何证明学会了

> 状态：draft · 来源核验：2026-09-06 · 数值例子为教学构造。

机器学习在有限样本上调整一个函数，然后要求它在未见过的输入上仍然有效。因此“训练误差下降”只完成了优化任务，能否泛化还需要独立证据。例如预测设备故障，把同一设备相邻时间片随机分进训练和测试，得到的高准确率可能只是记住设备特征。

## 1. 先把任务写成输入、输出和代价

| 问题 | 训练信号 | 常见输出 | 适合先做的基线 |
|---|---|---|---|
| 监督学习 | 输入与人工/业务标签 | 分类概率、回归值 | 多数类、线性/逻辑回归 |
| 自监督学习 | 从原始数据构造目标 | 下个 token、被遮挡内容、表征 | 简单预测或重构 |
| 无监督学习 | 没有目标标签 | 聚类、低维表示 | k-means、PCA |
| 强化学习 | 动作影响后续观测与奖励 | 策略 | 固定规则策略 |

分类回答“属于哪一类”，回归回答“是多少”，排序回答“哪个更应该排前面”。同一业务可有不同建模方式：检索可以学二分类相关性，但最终要评的是候选集合中的排序，不能只报告平衡样本上的分类准确率。

特征必须在预测时可获得。预测“今天会不会故障”却使用维修后的工单字段，就是标签泄漏。标签还要明确时间窗口、未知值处理和冲突规则；没有报修不一定等于没有故障。

## 2. Loss 帮助训练，Metric 回答业务问题

经验风险最小化写成：

$$\hat\theta=\arg\min_\theta \frac1n\sum_{i=1}^n\ell(f_\theta(x_i),y_i)+\lambda\Omega(\theta).$$

$n$ 是训练样本数，$\ell$ 是单样本损失，$\Omega$ 是复杂度惩罚，$\lambda$ 控制惩罚强度。均方误差强调大残差；绝对误差对极端值较不敏感；交叉熵让正确类概率上升。可优化的损失与最终收益往往不同，需要一起记录。

二分类中，Precision=$TP/(TP+FP)$，Recall=$TP/(TP+FN)$。例如 1,000 次请求中只有 10 个危险请求，全部预测安全也有 99% 准确率，却没有任何检出能力。这里把“危险”定义为阳性，规则是危险分数大于等于阈值才拒绝。提高这个阈值会减少被判为危险的请求，通常减少误报，同时增加漏报。TP 是正确检出的危险请求，FP 是被误拒的安全请求，FN 是被放过的危险请求。应该先明确漏报和误报的代价，再用验证集选择阈值，并在测试集上报告两个指标。分母为零时要明确返回规则，不能默默记为完美。

## 3. 数据划分决定评测回答哪个问题

| 数据结构 | 合理切法 | 随机逐行切分的风险 |
|---|---|---|
| 独立用户的新请求 | 按用户分组 | 学到用户身份，误当泛化 |
| 时间序列与设备监控 | 时间向前、必要时留间隔 | 未来信息和相邻窗口泄漏 |
| 文档切块与问答 | 按原始文档/问题族切 | 同一内容同时在训练和测试 |
| 独立同分布表格样本 | 分层随机划分 | 小类别数量失衡 |

标准化的均值、缺失值填充规则、词表、特征筛选都属于“拟合”。必须只在训练集学习，再应用到验证和测试。交叉验证时，每一折都重新拟合预处理；先对全数据标准化再交叉验证，会提前看到保留集分布。

```python
# X_train / X_test 事先按正确的抽样单位划分
mean = X_train.mean(axis=0)
scale = X_train.std(axis=0)
scale = np.where(scale == 0, 1., scale)
Z_train = (X_train - mean) / scale
Z_test = (X_test - mean) / scale
```

## 4. 为什么更复杂的模型会更差

模型太简单会无法表达规律，即欠拟合；模型过度追随训练集偶然噪声，会在新样本上误差增大，即过拟合。判断要同时看训练和验证曲线：两者都差先检查数据和表达能力；训练好、验证差先检查泄漏、样本量、正则化与分布差异，而不是继续增加训练轮数。

岭回归的一个写法是 $\|Xw-y\|^2+\lambda\|w\|^2$，闭式条件为 $(X^TX+\lambda I)w=X^Ty$。它通过抑制大系数降低对噪声的敏感度；如果偏置不应惩罚，就把对应对角元素设为零。注意这里损失没有除以 $n$，所以不能把另一种平均损失定义下的同一个 $\lambda$ 直接照搬。

在配套实验中，同一组少量带噪曲线用三阶、多项式高阶和高阶加岭惩罚拟合。测试点是预先固定、未参与拟合的均匀网格，标签来自无噪声真函数；它检查曲线恢复，不是独立随机业务请求的抽样评测。可以直接观察高阶模型的训练误差与测试误差分离，而不是只背“偏差—方差”四个字。

## 5. 分布偏移后应该改哪里

若训练时是短中文问题，上线主要是长代码任务，即使无泄漏，原测试集也不能代表线上。可以先区分输入分布 $p(x)$ 改变、标签比例 $p(y)$ 改变和条件关系 $p(y\mid x)$ 改变。它们不总能仅凭无标签日志识别；最终要抽样标注新的任务。

工程上保留输入长度、来源、任务类型等切片，分别比较质量、拒答和成本。只更新分类阈值可能解决标签比例变化，却无法让模型学会全新概念。新版本应在旧测试集与新场景集上同时回归，防止“适配了新场景，忘了旧场景”。

最小工作顺序是：定义预测时点与标签 → 按真实泛化对象划分 → 建简单基线 → 用验证集选参数和阈值 → 冻结后测试 → 按失败类型补数据。测试集看得越频繁，它越接近另一个验证集。
