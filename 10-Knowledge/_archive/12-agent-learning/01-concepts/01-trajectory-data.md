# 轨迹数据：把一次执行变成可以学习的样本

> 状态：draft · 来源核验：2026-09-06 · 教学示例均为本库原创，非生产成绩。

一个修复代码的 Agent 最后通过测试，不代表它中间的每一个动作都值得模仿。它可能先删了测试，又恢复测试；也可能靠泄露的答案成功。训练前首先要决定“什么行为是证据，什么行为是目标”。

## 轨迹比聊天记录多了什么

轨迹记为 $\tau=(o_0,a_0,o_1,a_1,\ldots,o_T)$。$o_t$ 是执行第 $t$ 个动作前 Agent 实际能看到的观察，$a_t$ 是模型产生的工具调用或回答。环境返回值是下一次观察的一部分；运行时错误、授权结果和最终验收不能被聊天文本替代。模型没有收到的日志不能事后塞进它当时的观察，否则会制造“先知道答案再决策”的训练样本。

下面是一条教学轨迹中一个动作的记录。`task_group` 表示同一个原始问题及其改写，`split` 按组分配；`tool_version` 用来辨认旧接口。

```json
{"task_id":"repair-17","task_group":"repoA-bug17","split":"train",
 "step":2,"observation":"test_discount failed: expected 90, got 100",
 "action":{"tool":"edit","args":{"path":"price.py","patch_id":"p1"}},
 "tool_version":"edit-v1","policy":"allowed","result":"applied",
 "model_version":"teaching-policy-v1","evaluator_version":"hidden-tests-v1"}
```

保留三个层次：原始执行日志用于追责和重放；脱敏、带完整性校验的轨迹用于分析；从轨迹提取的训练样本用于优化。不要直接覆盖原日志来“清洗”训练数据，清洗规则也需要版本。

## 成功、失败、合成数据分别怎么用

| 数据 | 值得保留的内容 | 常见错误 | 处理方法 |
|---|---|---|---|
| 验证成功轨迹 | 正确动作与可见反馈 | 把无用绕路全教给模型 | 按决策片段审查，保留必要上下文 |
| 失败轨迹 | 第一次偏离目标的位置 | 因失败而整条丢弃 | 用于错误分类或与修复轨迹组成偏好对 |
| 人工接管轨迹 | 接管前观察与实际纠正 | 把人工拥有的额外信息算成模型能力 | 明确接管点与信息差 |
| 合成轨迹 | 可控覆盖稀有错误 | 同一生成器重复自己的偏见 | 独立验证器筛选，保留来源标签 |

对失败轨迹做 SFT 时，不能只因为最终有一句“我错了”，就把前面的越权调用也作为正例训练。可以抽取“看到超时后查询请求状态”这一段作为目标，其前提是当时确实能查询状态。

## 去重和划分决定评测是否可信

相同仓库中同一个 bug 的中文、英文、换变量名版本应在同一组。先按来源、问题家族和时间划分，再在训练集内去重；仅做文本哈希抓不到语义改写。时间敏感任务还要保留文档和环境快照。

```python
from collections import defaultdict
splits = defaultdict(set)
for row in dataset:                       # dataset 是脱敏后的轨迹列表
    splits[row["task_group"]].add(row["split"])
assert all(len(s) == 1 for s in splits.values()), "同源问题跨集合泄露"
```

这条检查只能抓已正确标注的组；它不能自动发现隐藏近重复，也不能证明预训练阶段未见过公开测试题。报告应写“未发现本次数据管线的组泄露”，不要写“绝对无污染”。

## 从今天的数据开始

先选一类可自动验收的任务，记录观察、动作、工具结果和验收结果，人工抽查最常见的两类错误。完成来源和脱敏检查后，再决定抽取 SFT 样本还是偏好对。相关可运行检查见[轨迹与奖励实验](../04-labs/01-trajectories-and-rewards.ipynb)，完整函数在[learning.py](../05-code/learning.py)。[下一篇](02-sft-and-preference-optimization.md)解释哪些 token 会参与训练。[来源](../references.md)中的 SWE-agent 用于理解执行接口，DPO 用于理解偏好数据；本篇数据结构是教学设计。
