# 企业知识 Agent：同一问题在不同权限下有不同答案

> 状态：draft · 更新：2026-09-06

教学输入：A 团队文档写“预算 100”，仅 Alice 可读；B 团队文档写“预算 900”，仅 Bob 可读。两条文档都与“预算是多少”相关。案例目标是让 Alice 只能得到 A 文档，Bob 不能通过伪造 A 租户的查询读到它。数字与人员均为虚构教学数据。

如果先全库检索，再让模型“记得不要泄露”，其他租户内容已经进入模型输入。应在可信服务端取得租户和访问主体，将权限过滤加入数据访问路径；候选文档进入上下文前再次验证。文档来源需要随回答保存，以便用户打开原文时复核权限。

[代码](../../../05-code/application_cases.py)中的 `visible_documents` 同时检查 tenant 与 readers。实际输出只有 `['a']`，对 `(tenant='A', principal='bob')` 返回空列表。运行命令与测试入口见[代码说明](../../../05-code/README.md)。这只是列表过滤实验，没有部署身份服务或 PostgreSQL。

| 潜在失败 | 本地反例 | 生产扩展 |
|---|---|---|
| 只看相似度 | 两文档问题相似但权限不同 | 检索侧 ACL 过滤 |
| 只看租户 | 同租户并非所有人均可读 | 主体/角色与资源授权 |
| 缓存越权 | 用问题字符串当唯一键 | 权限版本与来源版本纳入键 |
| 撤回后仍可见 | 索引/摘要没有同步删除 | 派生对象来源依赖与删除传播 |

验收还应加入权限变更、缓存复用、事件补发和产物下载测试。只有本地过滤函数通过，不能宣称整套多租户隔离已完成。数据库层具体机制参考[PostgreSQL Row Security](https://www.postgresql.org/docs/current/ddl-rowsecurity.html)，并阅读[存储与多租户](../../../01-concepts/03-storage-and-multitenancy.md)中的角色绕过边界。
