# 世界模型与神经符号：预测后果和保证约束分别由谁做

> 状态：draft · 来源核验：2026-09-06 · 教学示例均为本库原创，非生产成绩。

> 研究快照：2026-09-06，固定代表论文版本用于学习。

让模型描述一张工厂地图，不足以称为可用于规划的世界模型。规划需要回答：在当前状态做某个动作，会到什么状态、得到什么回报、哪些后果不确定。神经符号方法则常把感知或候选生成交给神经网络，把明确规则和约束交给符号系统。

## 世界模型的最低功能

设潜在状态为 $z_t$、动作为 $a_t$，转移模型预测 $p_\phi(z_{t+1}|z_t,a_t)$，奖励模型预测 $\hat r_\phi(z_t,a_t)$。规划器在模型里比较候选动作序列，再在真实环境执行并观察偏差。世界模型可以预测像素，也可以只预测与任务相关的潜在状态和价值；逼真画面不是唯一目标。

可以先用人工规则理解“预测后果”：温度为 20，动作只能是加热 1 度或保持，目标是 22。假定转移是 `next_temperature = temperature + action`，那么 `[1,1]` 预测到 22，`[1,0]` 预测到 21；若最终奖励是 `-abs(temperature-22)`，两个计划得分为 0 和 -1。规划器选前者，但执行第一步后若只测到 20.5，就要从 20.5 重新规划。这与把“加热两次”存成永不检查的工作流不同。此处转移和奖励由我们给定；神经世界模型要从数据学习它们，还需评估预测误差。

[World Models v4（2018-05-09）](https://arxiv.org/abs/1803.10122v4)研究压缩时空表示和在模型环境中训练策略。[MuZero v2（2020-02-21）](https://arxiv.org/abs/1911.08265v2)结合学习模型和搜索，学习对规划有用的量。它们是在具体任务中验证的方法，不等于通用物理世界已被完整建模。

模型多步推演会积累误差。规划器还可能主动选择模型最乐观却最不准确的区域，这是模型利用问题。短视野滚动规划、真实反馈校正、不确定性惩罚和受限动作集可以降低风险，但各有成本，也不构成普遍保证。

## 神经与符号如何具体合作

举一个教学选型任务：候选生成器提出两个网络宽度，确定性程序检查参数量和延迟是否满足上限，只有合法候选进入评分。这样候选生成与硬约束校验分开。下面直接手填候选，尚未调用神经网络生成它们。

```python
candidates = [{'width':8, 'params':64, 'latency_ms':9},
              {'width':16, 'params':256, 'latency_ms':7}]
feasible = [x for x in candidates if x['params'] <= 100 and x['latency_ms'] <= 10]
assert [x['width'] for x in feasible] == [8]
```

这里的资源数字是教学数据，不代表真实硬件测量。符号检查能保证输入数字满足规则，但如果模型编造了参数量或测量过程有误，规则通过也没有价值。更强的方案由可信代码计算参数量、真实工具测量时延，再校验约束。

| 组合方式 | 神经部分 | 符号/确定性部分 | 主要边界 |
|---|---|---|---|
| 候选 + 约束 | 提出结构或计划 | 类型、资源、依赖校验 | 候选空间可能不充分 |
| 感知 + 规划 | 从图像识别对象/状态 | 搜索路径和规则 | 感知错误会传给规划 |
| 程序生成 + 执行 | 生成代码 | 解释器、测试、求解器 | 测试覆盖决定结论范围 |
| 学习模型 + 搜索 | 预测后果与价值 | 比较行动序列 | 模型误差可能被搜索放大 |

[研究算例](../05-code/research_checks.py)运行资源约束过滤；其中尚无状态转移模型，不能据此验证规划。它没有训练神经世界模型，也没有实现 MuZero。想把这些思想用到科研 Agent，先阅读[研究案例](../03-cases/01-research-and-science-agents.md)，明确提案、实验与证据之间的边界。
