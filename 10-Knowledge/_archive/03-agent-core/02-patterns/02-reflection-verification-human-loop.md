# 反思、验证器与人工介入：分别负责哪一种错误

> 状态：draft | 来源核验：2026-09-06

搜索之后，模型写出“所有任务都应使用固定20%的上下文做记忆”。语句流畅并不能说明证据成立。让同一模型再问自己“答案正确吗”，可能得到同样的错误结论。可靠做法是先定义能独立核查的条件，再决定哪些错误适合模型修订，哪些需要人判断。

| 机制 | 接收什么 | 返回什么 | 适合解决 | 不能保证 |
| --- | --- | --- | --- | --- |
| 反思 | 失败轨迹和具体反馈 | 下一次修改建议 | 漏步骤、错误查询、策略选择不当 | 反思本身可能误诊 |
| 验证器 | 产物和验收条件 | 通过、失败及可定位证据 | 格式、数值、测试、引用存在性 | 验证条件未覆盖的错误 |
| 人工介入 | 决策对象、风险和备选 | 确认、纠正、拒绝或补信息 | 目标歧义、不可自动判定取舍 | 无信息的人也难以判断 |

Reflexion 展示了用语言反馈影响后续尝试的研究方法。它不意味着运行时把一段“经验总结”写入记忆后，模型参数已经更新，也不能据此声称每次反思都会提高成功率。

## 先把“缺哪条证据”变成可执行检查

本例输出引用文档ID。最小检查可以发现伪造ID：

```python
import re

def check_citations(answer, documents):
    available = {doc["id"] for doc in documents}
    cited = set(re.findall(r"\[(doc-\d+)\]", answer))
    return {"has_citation": bool(cited), "unknown_ids": sorted(cited - available)}
```

但 `doc-1` 存在并不表示它支持答案中的每个主张。这个验证器只能验引用存在性；要检查支撑关系，还需把答案拆成主张，对照引用片段做规则或人工/模型判定，并测量误判率。不能在报告中把“引用ID都存在”写成“答案事实100%正确”。

## 修订循环要有退出条件

一次实用修订包含：保存当前候选，取得具体失败项，仅修改相关部分，再执行相同验收。若第二次仍缺证据，就应标注不足或请求补充资料。重复让模型“再仔细想一想”会增加成本，也可能为了通过表面规则而制造引用。

预算可以写成最多 $R$ 次修订：总尝试次数为 $R+1$。例如 $R=1$ 表示初稿一次、修订一次，不能让每个验证失败都重新生成一个新的“最多一次”计数器。计数必须属于任务状态，跨恢复保留。

## 人工介入应该给出可判断的对象

对于只读搜索，已有任务授权通常足够。若下一步是覆盖用户的正式报告，界面应展示目标文件、差异和影响，再等待明确决定。等待时保存 `waiting_for_input` 状态和决策ID，恢复时核对批准的对象仍与当前对象一致。不要只保存“用户同意了”而忘记同意的是哪份内容。
