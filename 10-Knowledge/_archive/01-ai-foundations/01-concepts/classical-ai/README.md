# 经典 AI：把问题变成可以搜索的状态空间

> 状态：draft · 来源核验：2026-09-06 · 代码使用人工构造的非负权图。

当环境规则已知、结果能检查时，不必把“下一步怎么走”全部交给语言模型猜。先把问题写成状态、动作、转移和目标，就可以用确定性搜索找到路径。这同样适用于 Agent 的工具序列、编译配置组合和有前置条件的任务规划。

## 1. 好的状态需要保留哪些信息

搜索问题由初始状态 $s_0$、合法动作 $A(s)$、转移 $T(s,a)$、代价 $c(s,a)$ 和目标判定 $G(s)$ 定义。状态必须包含影响后续合法动作和成本的信息。例如“工具已安装”和“有无认证”不能只写在对话里却不进入状态，否则两个看似相同的节点实际能执行不同动作。

环境给观测，智能体依据观测选择动作。如果观测不完整，就不能直接当成完整状态；需要维护历史摘要或信念状态，详见[强化学习](../reinforcement-learning/README.md)。搜索中的一个节点还保存到达该状态的路径及累计成本，状态相同不代表路径成本相同。

## 2. 六种搜索，差异在先展开谁

| 算法 | 排序规则 | 适用条件与代价 |
|---|---|---|
| BFS 广度优先 | 先展开较浅节点 | 单位边代价时找到最短步数；前沿可能指数增长 |
| DFS 深度优先 | 先走到底 | 栈占用较小；不保证最短，循环/无限深需限制 |
| UCS 一致代价 | 最小累计成本 $g$ | 非负边、合适终止条件下求最小成本 |
| Greedy 贪心 | 最小估计剩余成本 $h$ | 容易快但走弯路；一般不保证最优 |
| A* | 最小 $f=g+h$ | 好启发式减少展开；最优性依赖条件 |
| Beam Search | 每层只保留前 $k$ 个 | 限内存，可能永久剪掉正确解；束宽不是准确率保证 |

例：$S\to A=1,A\to G=8,S\to B=3,B\to C=1,C\to G=1$。BFS 可先找到两步的 $S,A,G$，成本 9；UCS 找到三步的 $S,B,C,G$，成本 5。这说明“步骤少”和“代价低”是不同目标。

## 3. A* 的启发式为什么不能乱写

$h(s)$ 估计从 $s$ 到目标的最低剩余代价。可采纳条件 $0\le h(s)\le h^*(s)$ 要求不高估；一致性 $h(s)\le c(s,a)+h(s')$ 要求沿边的估计变化不能超过实际代价，通常令目标 $h(G)=0$。

树搜索中可采纳启发式可支持最优性结论；图搜索若关闭节点后永不重新打开，需要更强的一致性等条件。配套实现允许发现更便宜路径后重新入队，并在出队时忽略过时成本记录。它仍要求非负边，且这里的有限图避免无限状态空间的终止问题。把语言模型随口给的“剩余难度”当 A* 启发式，并不能继承 A* 的最优性保证。

核心更新只做两件事：新路径更便宜时替换记录，以累计成本加剩余估计入队。

```python
candidate = g + edge_cost
if candidate < best.get(next_state, float('inf')):
    best[next_state] = candidate
    parent[next_state] = state
    heapq.heappush(frontier,
                   (candidate + heuristic(next_state), candidate, next_state))
```

不要在“生成目标节点”时立即停止，应该等目标按算法规则从前沿取出；否则其他尚未展开的路径可能更便宜。

## 4. MCTS 用采样分配搜索预算

当搜索树太大、启发式难写，但可以模拟后续结果时，可以用蒙特卡洛树搜索：选择已有分支、扩展节点、模拟结果、把回报回传。UCT 的一种选择分数为：

$$\bar Q(s,a)+c\sqrt{\frac{\log N(s)}{N(s,a)}}.$$

$\bar Q$ 是该动作的平均模拟回报，$N(s)$ 是父节点访问次数，$N(s,a)$ 是动作访问次数，$c$ 控制探索。第一项偏向已经表现好的动作，第二项给少试过的动作机会；未访问动作需单独优先处理，不能真的除以零。仿真错误、奖励投机或预算很小时，MCTS 也可能稳定选择错误方案。它解决预算分配，不负责自动保证模拟器可信。

## 5. 约束满足、规划和概率推理解决不同问题

约束满足问题把变量、取值域和约束分开。例如两项任务各需一个 GPU，且不能在同一时段占用同卡；回溯搜索先赋值，约束传播删除不可能值，最少剩余值启发式先处理最受限变量。与路径搜索相比，它关注一组赋值是否满足条件，不一定关心赋值过程本身。

经典规划把动作写成前置条件与效果，例如 `run_test` 要求 `code_ready`，执行后得到 `test_result`。这种表示便于检测缺依赖和非法顺序，但真实工具失败、状态过期时需要重新观测和规划。计划只是一个有条件的预测。

概率推理则从不确定证据更新判断。贝叶斯网络用有向图表达条件依赖，并按 $P(x_1,...,x_n)=\prod_iP(x_i\mid\mathrm{parents}(x_i))$ 分解联合分布；边表示建模的条件结构，不能不加假设就当成因果关系。诊断时可以计算故障后验，再把“检查哪个传感器”交给规划策略。
