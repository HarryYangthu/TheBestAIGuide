# 工作区、沙箱与产物：文件放在哪里不等于权限被限制

> 状态：draft；来源核验：2026-09-06；本地恢复与幂等实验已实跑，生产能力不在验证范围内。


给每个 Agent 一个不同目录，可以防止正常程序把临时文件混在一起；它不能防止程序读取目录之外的文件。工作区是组织文件的约定，沙箱才是执行权限边界。把这两者混淆，会让“代码在临时目录运行”被误认为“代码已经安全隔离”。

## 一个实验任务需要哪些目录与权限

以“运行候选模型并导出评测报告”为例：输入数据只读，代码位于本次 Run 的工作目录，输出写到独立产物目录。执行进程只得到此次所需的环境变量，网络连接默认由任务需求决定并限定目的地，而不是继承宿主机所有权限。

| 对象 | 设计方法 | 防止的具体问题 |
|---|---|---|
| 输入材料 | 按版本挂载只读副本 | Agent 改写输入后再声称结果可复现 |
| 临时工作区 | 每次 Run 独立路径 | 上一轮输出污染下一轮 |
| 执行边界 | 限制 CPU、内存、进程、磁盘与网络 | 无穷循环、无限写文件、未授权联网 |
| 凭据 | 由工具服务注入短期最小权限凭据 | 模型看到或日志打印长期密钥 |
| 产物目录 | 从允许路径采集，检查类型与大小 | 将任意系统文件当产物导出 |

本库本地 Runtime 使用临时目录与 SQLite，不执行不可信代码；因此没有实现容器、虚拟机或网络沙箱。生产项目需要选用实际隔离机制并验证限制生效，不能把本例深拷贝或目录约定当替代品。

## 产物必须能追到产生它的输入

文件名 `report-final-final.md` 没有说明输入版本、步骤和运行参数。可保存一份产物清单：

```json
{
  "artifact_id": "report-001",
  "run_id": "run-42",
  "step_id": "render-report",
  "relative_path": "outputs/report.md",
  "media_type": "text/markdown",
  "sha256": "由实际文件字节计算的摘要",
  "input_version": "fixtures-v1"
}
```

这是数据结构示意，摘要文本不是实际哈希。哈希证明当前文件字节与记录相同，不证明报告结论正确。还需要任务验证器检查内容。

相对路径校验至少要先做规范化，再确认最终路径仍处于工作区。仅检查字符串不含 `..` 不够，符号链接也可能指到外部。若文件可由不可信进程同时修改，还存在检查后替换的竞争窗口，需要操作系统级约束与安全的文件打开方式。

## 浏览器也有工作区状态

浏览器 Cookie、登录态、下载目录和页面缓存都属于运行环境。两个租户共用浏览器上下文，可能让 A 的任务读到 B 的会话。每个授权主体使用隔离的会话环境，下载文件保存来源 URL、时间和内容哈希；外部页面里的文字作为数据处理，不获得新的系统权限。

截图只能证明某个时刻页面看起来怎样，不能证明后端已完成动作。需要服务端回执、页面最终状态或下载文件校验共同确认。相关安全边界见[身份权限](../../11-safety-security-governance/01-concepts/02-identity-and-permissions.md)。

## 清理要跟随运行生命周期

成功时提交产物再清理临时文件；失败时保留必要诊断数据且避免保存 secrets；取消时终止子进程并回收资源。保留多久、谁能读、如何删除要有明确策略。临时目录自动清理适合本地教学，带审计要求的系统应把必要记录保存到受控存储。

工程安全背景参考 [NIST SP 800-207](https://csrc.nist.gov/pubs/sp/800/207/final)。这里按资源检查权限的做法由其原则启发，文件布局与清单为本库教学设计。返回[运行时导航](../README.md)。
