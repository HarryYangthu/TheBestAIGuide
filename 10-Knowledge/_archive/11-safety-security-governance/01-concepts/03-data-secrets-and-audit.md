# 数据、密钥与审计：记录足够的信息，不复制所有信息

> 状态：draft；来源核验：2026-09-06；配套实验验证本地权限边界，不代表真实模型注入免疫。


工具响应里有实验摘要和 API 密钥，模型只需要摘要。最直接的保护不是要求模型忘掉密钥，而是从一开始就不把密钥传进去。数据最小化首先是字段选择问题，然后才是输出过滤问题。

## 在每次传递前缩小数据

本地记录包含 `tenant`、`text` 和一个教学 secret 字段。阅读工具不直接返回整个记录，而是显式构造允许字段：

```python
return {"id": resource_id, "text": record["text"]}
```

这个 allowlist 投影不会把新增的内部字段自动带到模型上下文里。反过来，`return dict(record)` 再删除几个已知敏感字段，容易在未来新增字段时遗漏。字段名检查也不够，正文里嵌入敏感信息仍需其他处理；本例验证的是结构化 secret 字段没有进入输出。

| 数据位置 | 应限制什么 | 常见遗漏 |
|---|---|---|
| 检索结果 | 主体可见记录与必要片段 | 检索前未过滤，模型已看到全文 |
| 工具响应 | 允许字段、长度和敏感内容 | 原始调试对象含凭据 |
| Agent 记忆 | 用户、来源、有效期和用途 | A 用户记忆被 B 用户召回 |
| Trace | 标识、状态、脱敏参数与回执引用 | 记录完整 Authorization 头 |
| 产物 | 来源、访问权限、保留策略 | 导出文件绕过原权限 |

## 密钥应该在哪里出现

真实密钥由受控工具服务从 Secret Store 或受保护环境取得，模型只选择合法工具和参数。尽量使用短期、范围受限凭据。不要把密钥写进 Prompt、Notebook 输出、Git 仓库或异常堆栈。

“日志删掉密钥”不代表所有副本已清除：缓存、错误追踪、下载文件和备份都可能有副本。若密钥已经泄露，立即撤销或轮换比只删除日志更关键。轮换需要检查依赖服务是否切换到新凭据，再确认旧凭据已失效。

## 审计要回答哪几个问题

出问题时，至少应知道：哪个用户在什么 Run 中请求了什么动作，作用于哪个资源，策略允许还是拒绝，动作是否真的执行成功。完整自然语言对话常常既泄露数据，又不能准确回答这些问题。

本例审计事件包含 `run_id/user/tool/resource_id/decision/reason`，不记录原文和 secret。测试通过后可以追查越权来自哪类动作，同时不复制记录正文。`reason=resource_not_accessible` 同时用于资源不存在和无权访问，避免向调用方暴露其他租户资源是否存在。

本例 audit 是内存列表，不能抗进程崩溃或篡改。生产日志需要访问控制、可靠持久化、保留期限，并把动作回执与事件关联。哈希链可以帮助发现已保存事件被修改，但如果没有可信的外部锚点，也不能独自证明日志从未被整体替换。

## 删除必须覆盖派生物

删除一篇文档，除了主文件，还可能要清理分块、Embedding、摘要、缓存和以它为来源的记忆。只删文档表的一行，搜索索引仍可能返回原内容。应维护来源到派生对象的映射，删除后重新查询验证，记录尚未清除的范围。

如果审计制度要求保留某些事件，可以保留资源 ID、删除动作和时间，避免保留已要求删除的全文。具体保留期限取决于组织制度和适用要求，本篇不提供法律合规结论。
