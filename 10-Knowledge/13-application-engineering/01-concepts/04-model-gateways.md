# 模型网关：统一接口之后仍要保留能力差异

> 状态：draft · 来源核验：2026-09-06 · 教学示例均为本库原创，非生产成绩。

把所有厂商响应都改成同一个 JSON 结构，只解决了接线问题。工具调用、结构化输出、图像输入和上下文长度可能不同；回退到另一模型时，任务语义也可能变化。

## 网关到底做什么

网关接收内部请求，选择满足能力和预算约束的 Provider Adapter，转换消息、解析事件、统计用量并标准化错误。业务层保留 Run 与工具执行权；不能让网关把文本中的函数名直接变成外部副作用。

先定义需求集合，例如 `{tools, json_schema}`。候选模型只有能力覆盖需求才能被选择；再比较预计成本和时延。厂商能力和价格会变化，应来自维护的配置与探测，不要硬编码一张永不过期的排行榜。

$$m^*=\arg\min_{m\in\mathcal M_{\rm eligible}}\left[\widehat C_m+\lambda\widehat T_m\right].$$

$\widehat C_m$ 是根据输入量估算的成本，$\widehat T_m$ 是同类任务的预计时延，$\lambda$ 把时间折为业务权重。这个目标只在候选已满足质量、权限和能力下使用；最低价格不等于最低成功任务成本。

## 回退必须按失败阶段区分

| 失败 | 是否适合自动回退 | 原因 |
|---|---|---|
| 请求发出前发现配额不足 | 可在能力等价候选中回退 | 尚未产生回答或动作 |
| 明确 429/临时服务错误 | 有限重试/回退 | 需要统一总预算与退避 |
| 已流出一半文本 | 重开一次并标明替换 | 不能拼接两模型半段回答 |
| 已返回工具调用并开始执行 | 先确认工具结果 | 回退可能重复外部动作 |
| 内容策略拒绝 | 不用换供应商绕过 | 应按任务边界处理 |

上下文压缩也不能静默截断系统规则以适应更小模型。若回退候选容纳不了必要输入，应返回可解释的失败或先执行经过验证的压缩策略。

## 成本按一次 Run 归集

$$C_{\rm run}=\sum_j(n^{(j)}_{\rm in}p^{(j)}_{\rm in}+n^{(j)}_{\rm out}p^{(j)}_{\rm out})+C_{\rm tool}+C_{\rm storage}.$$

$j$ 是每次模型请求，token 数与对应单价必须使用相同计量单位；缓存、批量和特殊计费按供应商实际规则扩展。失败、重试和并行候选同样计费，不能只统计最后一条成功回复。本库[案例代码](../05-code/application_cases.py)演示能力过滤和预算选择，所有单价都是教学单位。[生产成本篇](../../14-production-engineering/01-concepts/02-slos-reliability-and-cost.md)进一步计算单位成功任务成本。

这里给出供应商中立设计；SSE、身份与配额基础规范见[来源](../references.md)。真实接入前应以目标供应商当前官方 API 文档和契约测试验证兼容性。
