# 接入与解析：先确认知识没有在入口处变形

> 状态：draft
> 资料核验：2026-09-06；本域演示 UTF-8 接入；进阶工程已执行 PDF 文本提取，未执行 OCR。
> 前置：[RAG 端到端流程](01-rag-pipeline.md)

如果原文写的是“电压低于 10 V **不得**重启”，解析结果丢掉“不得”，后面的检索和生成即使完全正确，也只会把错误步骤讲得更像真的。接入首先要解决的是：让机器拿到的内容与原文一致，并且保留结论成立的条件。

## 文本、顺序和结构是三个不同问题

| 输入 | 容易拿到什么 | 还缺什么 | 需要检查的反例 |
| --- | --- | --- | --- |
| Markdown、纯文本 | 字符和标题标记 | 编码、代码块、相对附件路径 | 文档不是 UTF-8，却静默替换乱码 |
| 有文本层的 PDF | 文本块及坐标 | 阅读顺序、页眉、双栏关系 | 左栏一句话插入右栏另一段 |
| 扫描 PDF、图片 | 像素 | OCR 识别、版面结构 | `0/O`、负号、下标、单位误识别 |
| 表格 | 单元格文本 | 行列、合并单元格、表头范围 | A 型号参数被配到 B 型号 |
| 网页 | DOM 文本 | 正文区域、动态数据、抓取时间 | 导航栏和旧评论覆盖主文 |

OCR 负责识别“写了哪些字”；版面分析负责判断“这些字属于哪里”；表格重建负责保留“哪一行与哪一列对应”。一种工具可能同时做这三步，但评测时必须拆开。Docling 的报告将版面分析和表格结构识别作为不同组件介绍，这可以帮助理解分工，不能据此假定它能正确解析自己的全部资料。[1]

## 先定义中间表示，再选解析器

下面是虚构手册的一条规范化记录。`source` 指向原文件，`location` 指向原文位置，`content` 是检索消费的表示。它们承担不同职责，不能只保存 content。

```json
{
  "source_id": "demo-manual",
  "source_version": "2",
  "parser": "manual-normalization-v1",
  "location": {"page": 3, "block": 7, "bbox": [20, 80, 580, 160]},
  "kind": "table_row",
  "content": "型号=DEMO-A；电压条件=<10 V；动作=不得重启",
  "raw_text": "DEMO-A | <10 V | 不得重启",
  "review_required": false
}
```

这些字段是本库设计示例，不是某个解析工具的原生 API。坐标必须说明单位、原点和页面旋转；页码必须说明从 0 还是从 1 开始。否则所谓“可定位引用”仍会指错地方。

将表格转换成句子时，要把列标题带上。把 `DEMO-A | <10 | 不得` 直接做向量，模型不知道 10 的单位，也不知道“不得”针对什么动作。保留表格原件，是为了读者能核对转换结果，不必相信一次自动改写。

## 哪些信息必须原样保护

编号、数字、单位、否定词、条件和步骤依赖应列为关键字段。例如 `ALM-12003` 与 `ALM-12030` 只差两位，但不能自动纠错为同一个值。原文里 `≤` 不能为了“清洗特殊字符”变成 `<`；上下标也不能无条件去掉。

可以把解析质量分成两层。字符错误率看整体转录误差：

$$
\mathrm{CER}=\frac{S+D+I}{N}
$$

其中 $S,D,I$ 分别是替换、删除和插入字符数，$N$ 是人工参考文本字符数，分母为零的空页另行统计。参考文本有 100 个字符，发生 2 次替换和 1 次删除，CER 为 3%。这只是计数例子，未运行 OCR。

但 3% 的错误可能全落在标点，也可能恰好落在三个故障码上。因此还要单独统计关键字段精确正确率，以及“型号—条件—动作”三元组是否完整。指标合格不替代高风险步骤抽查。

## 一条可以实施的接入流程

1. 登记来源 ID、租户、权限、版本和原始文件哈希。重复上传时比较内容，不只比较文件名。
2. 根据文件实际内容识别格式；无法解析就返回明确失败，不创建“成功但为空”的索引记录。
3. 解析成块，保留原始坐标和顺序。把页眉等噪声作为可解释规则过滤。
4. 对关键字段做规则校验，低置信或冲突项进入复核队列。不要把 OCR 置信分直接当事实正确概率。
5. 写入候选索引并跑固定查询集；通过后再切换在线索引。失败时旧版本继续服务。

## 从代码开始

本仓先实现最容易复现的 UTF-8 Markdown 和 JSONL 接入。它直接暴露能力边界，不尝试把二进制 PDF 当文本读。

```python
from rag_pipeline import load_markdown, Index

doc = load_markdown("manual.md", doc_id="manual", tenant="alpha",
                    product="DEMO-A", version="2")
index = Index()
index.upsert(doc)
```

完整代码在 [ingest.py](../05-code/rag-pipeline-python/src/rag_pipeline/ingest.py)。运行入口见[工程说明](../05-code/rag-pipeline-python/README.md)。进入 PDF/OCR 时保留同样的来源契约，把解析器输出转换为有来源的文档块，再进入[切块与元数据](04-chunking-and-metadata.md)。本域的 `Document/Chunk` 只保留字符偏移。进阶工程的 [documents.py](../../../20-Projects/learning-workbench/src/learning_workbench/documents.py)与[多模态教学任务](../../../20-Projects/learning-workbench/src/learning_workbench/practice.py)已处理自制 PDF 的文本和页码，也记录文本起点坐标；起点不是整段的精确包围框。OCR、复杂版面重建仍未执行，不能用文本层提取成功来证明它们有效。
