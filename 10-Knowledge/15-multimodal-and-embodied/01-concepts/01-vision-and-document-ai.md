# 视觉与文档：模型看到了字，为什么仍会读错表

> 状态：draft · 来源核验：2026-09-06 · 教学示例均为本库原创，非生产成绩。

一页报告里有两列数字、一个跨列标题和一条“单位：毫秒”的脚注。OCR 可以把每个字识别正确，却把第二行的数接到第一行。文档理解需要同时保留内容与空间关系。

## 从像素到视觉 token

ViT（视觉 Transformer）把图像切成固定大小的 patch（小图块）。若图像为 $H\times W$，patch 边长为 $P$，在整除且不额外裁剪的简化情况下，patch 数为 $N=HW/P^2$。每个 patch 展平后维度为 $P^2C$，其中 $C$ 是通道数，RGB 图像为 3；再线性投影到模型隐藏宽度 $D$，并加入位置信息，形成 Transformer 输入。

例如 $224\times224$ 的 RGB 图像用 $16\times16$ patch，得到 196 个 patch，每个展平为 768 维。这里的“768”来自 $16\cdot16\cdot3$，不是所有模型的隐藏维度。特殊 token、图像切片和高分辨率策略会改变真实 token 数。

VLM（视觉语言模型）把视觉表示与语言模型连接，使文本查询能够利用图像特征。能描述图像不等于能准确读取小字号、坐标、计量单位和密集表格；模型对这些细节的误差必须通过任务数据评测。

## 三条文档处理路线

| 路线 | 保留的信息 | 适合场景 | 主要风险 |
|---|---|---|---|
| 原生 PDF 文本解析 | 字符、部分位置与字体 | 可复制文本的报告 | 阅读顺序与表格关系仍可能错 |
| OCR + 版面/表格解析 | 文字框、区域、行列 | 扫描件和图片 | OCR 与结构误差叠加 |
| 页面图像输入 VLM | 视觉关系和文本语义 | 复杂图表、混合布局 | 细数字误读、成本与引用定位 |

实践常混合使用：优先利用可验证的文本层，复杂区域增加视觉理解，最终把数值与原区域核对。只保存一段“页面摘要”会丢失以后追溯的能力。

## 证据结构需要哪些字段

一条表格证据至少关联文档版本、页码、区域框、表名、行名、列名、单位和原始文本。例如“模型 B 的 P95 为 120 ms”需要同时指向 B 行、P95 列和单位。矩形通常记为 `[x0,y0,x1,y1]`，要声明是像素坐标还是归一化坐标，以及原图尺寸、坐标原点和轴方向。本域人工表使用左上角原点、x 向右、y 向下的归一化坐标；实际 PDF 常用左下角原点，不能原样叠到网页截图上。

```python
cell = {"doc_id":"latency-v1", "page":1, "row":"B", "column":"p95",
        "value":120, "unit":"ms", "bbox":[0.55,0.42,0.72,0.50]}
x0, y0, x1, y1 = cell["bbox"]
assert 0 <= x0 < x1 <= 1 and 0 <= y0 < y1 <= 1
```

本库[文档证据实验](../04-labs/01-document-evidence.ipynb)从人工标注的二维表格出发，展示扁平数字检索如何丢失行列语义，再执行结构检索与引用检查。它没有运行 OCR、ViT 或 VLM，因此不能用实验结果宣称视觉识别准确率。实现见[evidence.py](../05-code/evidence.py)。要把手填证据接到文件上，再跑[工作台媒体任务](../../../20-Projects/learning-workbench/README.md)，查看原创 PDF、提取文字、页码与 `origin_pdf_points`。这是文字起点，不是精确边界框；第三页无文字会提示需 OCR（光学字符识别），并未自动识别该页。理论出处：[ViT](https://arxiv.org/abs/2010.11929)；视觉页面检索实例：[ColPali](https://arxiv.org/abs/2407.01449)。
