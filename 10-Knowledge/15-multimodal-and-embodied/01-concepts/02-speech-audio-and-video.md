# 语音、音频与视频：时间轴也是上下文

> 状态：draft · 来源核验：2026-09-06 · 教学示例均为本库原创，非生产成绩。

一段会议录音转写出了“明天发布”，但没有记录谁说的、是否被后一句否定、明天相对哪一天。单纯的文字转写不是完整会议理解。音视频系统需要保留时间、说话人和证据片段。

## 音频输入如何进入模型

波形是按采样率记录的振幅序列。短时傅里叶变换把局部时间窗变成频率表示，Mel 滤波把频率能量汇聚到近似听觉尺度，常再取对数。采样率、声道数、重采样和归一化必须与模型输入约定一致。将 48 kHz 波形直接标记为 16 kHz，会使时长和频谱解释都出错。

ASR 输出识别文本；说话人分离区分声音来源；VAD 判断什么时候有人声；语音合成把文本变成声音。这些任务不能因为都处理音频就混成一个成功指标。Whisper 是语音识别研究的一个具体入口，不是所有语音生成系统的统一架构。

$$\mathrm{WER}=\frac{S+D+I}{N}.$$

$S,D,I$ 分别是相对参考转写的替换、删除和插入次数，$N$ 是参考词数。参考有 10 个词，替换 1 个、漏掉 1 个、多出 1 个，WER 是 .3；插入过多时它可超过 1。中文要明确分词方式，也可报告 CER。转写词错率低不保证任务正确，姓名、金额和否定词应单独检查。

## 视频不是一张更大的图片

视频包含时间顺序和声音。固定每秒抽一帧可能漏掉持续 0.2 秒的事件；抽更多帧会增加成本并产生重复信息。选择采样率需要依据事件持续时间和允许漏检程度，不能默认“帧越多越准确”。

```python
def covered(event_start, event_end, sampled_seconds):
    return any(event_start <= t <= event_end for t in sampled_seconds)
assert not covered(1.2, 1.4, [0, 1, 2, 3])
```

这个例子只说明采样可能漏掉事件，不是任何视频模型的性能测试。检索结果需要返回 `(video_id,start_seconds,end_seconds)`，而不是仅有截图。推断“先按按钮后报警”需要对齐两个时间戳；不同摄像头还可能有时钟偏差。

## 生成和实时系统的边界

扩散式生成可以从噪声逐步恢复图像或视频，也有其他生成范式。生成的逼真度不等于事件真实性；生成帧不能作为真实视频的证据。实时语音还涉及端点检测、打断、回声与音频缓冲，延迟应从用户说完到可听响应测量，不能只报模型首 token 时延。

| 失败 | 可观察证据 | 处理 |
|---|---|---|
| 静音被转写成内容 | 无人声区间出现句子 | VAD、静音反例、模型置信辅助 |
| 人名和数字错 | 与原音频不一致 | 保存片段并人工复核关键字段 |
| 事件顺序错 | 不同片段时间未对齐 | 统一时间基准、保留偏差 |
| 用户打断后仍播放旧回答 | 播放缓冲未取消 | 取消 token 与播放队列一起处理 |
