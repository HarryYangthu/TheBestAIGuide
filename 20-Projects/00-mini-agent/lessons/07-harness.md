# 07：让“完成”有可检查的含义

Harness 是模型周围负责运行与检查的程序。在这个项目中，它包括工具边界、步数预算、轨迹记录、结果验收和批量实验。前几章已经逐步加入这些部件，这一章把它们组织起来。

```bash
python 20-Projects/00-mini-agent/learn.py --output .runs/mini-final
```

[harness.py](../mini_agent/harness.py) 实际运行七个阶段，随后检查上下文裁剪、记忆覆盖与删除、并行结果一致、预算耗尽、引用错误。完成报告列出各项结果，不用一段“做得很好”的模型点评代替验收。

固定任务的独立检查在 [evaluate.py](../mini_agent/evaluate.py)：

| 检查 | 失败例子 |
| --- | --- |
| 模型正常结束且清单存在 | 步数耗尽；模型说完成但没有写文件 |
| 三项变更恰好齐全 | 漏掉 retry；重复 auth |
| before/after 正确 | 用废弃稿的 5 秒替代正式版的 10 秒 |
| 新旧引用的路径、行号、完整原文正确 | 引用 preview.md；原文是真的但引用错了行 |
| 格式符合当前请求或记忆 | 请求表格却保存了其他格式标记 |

答案文件由宿主读取，模型的读取工具无法访问它。这个设计适合固定教学资料；换新任务时，必须同步设计新验收条件。验收采用字段精确匹配，不评价开放式文风；同义改写可能失败，这是本项目刻意采用的受控范围。

**练习：** 复制一次运行目录，修改 `report.json` 中 auth 的 after，再运行 `run.py verify`。应出现 `auth:values=FAIL`。对照真实引用但错误结论的情况，解释“有引用”为什么不够。

项目完成需要三个层面的证据：机制运行通过、真实模型固定任务通过、你能解释并修正失败。第一层可以完全离线完成；后两层需要你自己的运行与实验报告。参考记录不替代自己的结果。
